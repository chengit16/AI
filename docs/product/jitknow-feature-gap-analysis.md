# 参考站个人空间、公司空间与当前项目功能差距分析

> 文档状态：待产品决策
> 调研日期：2026-08-21
> 参考对象：`https://aiknow.jitword.com` 个人空间与公司空间
> 当前项目：AI 智能平台
> 调研方式：参考站登录后页面走查与有数据流程实测，结合当前仓库页面路由、前端 API Service、后端 HTTP 路由、领域模型、持久化模型和阶段验收资料进行静态核对

## 1. 文档目的

本文档用于回答以下问题：

1. 参考站个人空间和公司空间分别有哪些页面、功能和增删改查动作。
2. 当前项目已经具备哪些对应能力，哪些只有后端底座，哪些完全缺失。
3. 若将当前项目改造成与参考站大致相同的产品，需要新增或改造哪些内容。
4. 哪些能力可以直接复用，哪些属于中大型新增模块，是否值得纳入由产品负责人最终决定。

本文档是产品范围决策材料，不代表已经批准开发，也不改变当前项目进度看板中的阶段状态。

- `C`：创建、导入、上传、邀请、新建版本等新增动作。
- `R`：列表、详情、搜索、筛选、统计、预览、下载等读取动作。

### 2.4 有数据端到端验证摘要

#### 2.4.1 个人知识生产与 RAG

1. 创建文件夹“产品知识库”并开启 RAG，创建在线文档“产品使用手册”。
2. 在编辑器写入正文并等待自动保存，返回知识库后确认正文长度变化并自动索引为 1 个 Chunk。
3. 在解析详情查看字符数、分块数、来源、索引状态和解析预览；实际编辑 Chunk 后触发重新嵌入，并完成 Chunk 禁用与恢复启用。
4. 实际导出 Markdown；创建文档分享，切换为密码访问并设置 7 天有效期。
5. 创建标签“产品指南”并应用到文档；创建术语“人工智能”及别名“AI”“智能助手”，完成停用和重新启用。
6. 创建网页连接器“帮助中心同步”，同步 `https://example.com/` 后生成“Example Domain”文档；再次同步未重复新增文档，验证同 URL 幂等替换语义。
7. 文档 AI 实际调用“一句话总结”，得到模型结果并插入正文；个人 AI 助手实际问答并产生引用、反馈和记忆数据。

#### 2.4.2 场景、工作流与办公 Agent

1. 创建场景“客户支持助手”，完成基础配置、高级参数、检索策略、记忆、护栏和效果预览，实际调用模型后保存草稿并应用到 AI 助手。
2. 从“默认 RAG 助手”模板创建“客户支持工作流”，实际修改节点、补齐重试分支连线并保存。
3. 模板初始保存被“存在不可达节点：queryRewrite”阻断；建立 `sufficiencyGate -> queryRewrite -> retrieve` 回路后图校验通过，证明发布前存在真实拓扑校验。
4. 工作流试运行实际执行输入审核和知识检索，显示运行成功、耗时和召回片段；随后发布为 `v1.0.1`。
5. 验证 Cron、Webhook、事件三类触发器表单及 Secret/事件名/任务指令；未创建外部触发器。
6. 办公 Agent 继承已发布工作流，验证快捷任务、历史记录、文件上传入口和 Word 导出。一次自定义需求提交后生成了空闲会话但未产生正文，说明办公 Agent 运行闭环仍有异常。

#### 2.4.3 公司空间数据流

1. 在“西西科技”保存企业描述，创建“客户成功部”，验证部门编辑/删除入口和成员角色、部门、职位、部门管理员字段。
2. 创建分类“客户服务资料”和企业文档“客户支持服务手册”；审计日志立即记录创建文档事件，企业控制台文档数和知识增长趋势从 0 变为 2。
3. 创建团队空间“客户支持知识空间”后，企业知识库页面仍显示“暂无团队空间”，但该空间实际出现在通用知识库文件夹树中；开启 RAG 后创建“客户服务指南”并自动索引为 1 个 Chunk。
4. AI 企业大脑随后识别到 1 个知识空间，实际回答响应时限问题并引用“客户服务指南”，也实际生成了月度工作总结报告模板。
5. 公司 AI 助手和公司 RAG 命中测试均只召回公司文档，核心检索数据按空间隔离；但企业大脑在公司尚无知识空间时曾显示个人空间的热门问题和近期活动，属于参考站统计/历史隔离风险。

#### 2.4.4 参考站实测异常，不应照搬

| 异常 | 实际表现 | 当前项目设计要求 |
| --- | --- | --- |
| 企业分类权限状态不一致 | 创建时选择“私有”，创建后卡片仍显示“公开” | 创建命令必须返回最终访问策略，服务端授权与页面标签使用同一事实源 |
| 团队空间双入口不同步 | 创建成功后企业知识库仍显示空状态，通用知识库却出现同名文件夹 | 明确定义“文件夹、知识库、企业分类、团队空间”的唯一领域关系，禁止双写和前端拼接 |
| 企业大脑历史疑似跨空间 | 公司无知识空间时显示了个人问答热门问题和活动 | 所有查询、对话、聚合和缓存键必须强制包含 `workspace_id`，增加跨空间安全测试 |
| 企业统计口径不一致 | 企业大脑今日调用为 3，企业控制台本月 AI 调用仍为 0 | 统一事件口径、时间窗、最终一致性延迟和指标数据源 |
| MCP 搜索跨空间泄露 | 在“西西科技”公司空间运行 `knowledge_search` 时，结果包含个人空间的 AI Coding 文档 Chunk | MCP、Open API、工具运行时必须从可信 `RequestContext` 取得 `workspace_id`，服务端强制过滤并增加跨空间回归测试 |
| 办公 Agent 运行无结果 | 提交需求后创建空闲会话但无正文；Word 导出仍提示成功 | 导出前校验可导出内容，运行状态、错误和重试必须可见 |
| 审计导出无反馈 | 点击导出后没有下载事件、成功提示或错误提示 | 导出使用异步任务并展示进行中、完成、失败和下载有效期 |
| 模型回答知识外推 | 个人问答声称文档未记载的实时协作、评论等能力 | 默认要求引用约束、无证据降级、事实一致性评估和反馈闭环 |

## 3. 执行摘要

### 3.1 核心结论

不建议重新创建技术项目，建议在当前仓库上新增“内容工作台与产品化体验”阶段。

原因如下：

1. 当前项目已经具备个人/企业空间隔离、成员与组织、RBAC/ABAC、套餐配额、知识入库、RAG、SSE 问答、工作流审批、Agent 发布、服务灰度、工具执行、审计和生命周期治理等高成本底座。
2. 参考站相对当前项目的主要优势不在底层安全和运行治理，而在个人知识管理、在线文档创作、AI 写作、公开分享、助手市场、企业知识门户等用户产品层。
3. 重新立项会重复建设当前项目已经完成的工作空间隔离、权限、检索、Worker、审计、审批和 Agent 运行能力，同时增加数据迁移与双系统维护成本。
4. 这不是简单换皮。在线编辑器、文档正文模型、自动保存、协作、分享、连接器和公开发布会新增较大领域模型与安全边界；其中在线编辑器已确认不进入第一版，保留为第一版完成后的独立候选能力。

### 3.2 总体差距分布

| 领域 | 当前基础 | 与参考站差距 | 判断 |
| --- | --- | --- | --- |
| 个人/企业空间 | 已有空间创建、切换、邀请、加入、停用和隔离 | 缺公司资料编辑、邀请链接门户和更完整空间入口 | 小到中改造 |
| 企业治理 | 组织、岗位、角色、RBAC/ABAC、动态菜单、审计底座较强 | 角色权限矩阵和审计日志缺独立产品页面，成员编辑体验不同 | 以后端复用为主的中改造 |
| 知识入库 | 上传、解析、OCR、Chunk、索引、发布、重试较完整 | 缺文件夹、标签、收藏、回收站恢复、术语和连接器产品链路 | 中到大改造 |
| 在线文档 | 只有文档元数据、来源、不可变版本和原文件 | 缺正文编辑器、自动保存、历史、导入导出、分享和协作 | 大型新增模块；已确认第一版后再评估 |
| AI 问答 | 私有会话、SSE、引用、反馈和取消较完整 | 缺快捷指令、范围筛选、回答场景、文件临时上下文和公开发布 | 中改造 |
| 场景引擎 | Agent JSON 草稿、知识范围和模型网关可复用 | 缺面向普通用户的结构化场景配置、检索策略和预览页 | 中到大改造 |
| 工作流/Agent | 版本、测试、审批、发布、运行和运营治理强 | 缺参考站式模板、办公 Agent 场景页和低代码节点体验 | 中改造 |
| MCP/工具 | 内部工具目录、确认、取消、SSE 和历史已有 | 缺标准 MCP 外部服务出口和参考站式调试/注入扫描产品页 | 中到大改造 |
| 公开生态 | 无公开助手管理和广场 | 缺发布权限、公开访问、排行、作者页和滥用治理 | 大型新增模块 |
| 企业知识门户 | 企业空间可用知识、问答和审批底座 | 缺分类门户、团队空间、企业大脑和经营统计页面 | 中到大改造 |

## 7. 个人空间与公司空间差异

| 维度 | 个人空间 | 公司空间 |
| --- | --- | --- |
| 空间主体 | 单一所有者 | 所有者、管理员、普通成员和部门管理员 |
| 通用功能 | 工作台、知识、AI、Agent、工具、收藏等 | 保留个人空间通用功能 |
| 组织治理 | 无 | 部门、职位、成员归属和团队邀请 |
| 知识治理 | 个人文件夹、标签、术语和连接器 | 增加企业分类、团队空间、部门可见和文档审批 |

| AI 入口 | 个人 AI 助手和办公 Agent | 增加多知识空间联检的 AI 企业大脑 |
| 统计 | 我的文档、收藏、调用等 | 增加成员、存储、文档访问、知识增长和企业活动 |
| 品牌 | 用户头像与资料 | 企业名称、Logo 和描述 |
| 数据隔离 | 仅个人工作空间数据 | 通用知识、会话和 RAG 召回按公司隔离；聚合历史仍发现参考站风险 |

企业空间不会使技术实现量简单翻倍。当前项目的 `workspace_id` 隔离、组织和权限底座可以复用，但公司门户、分类、统计和成员操作体验仍需单独建设。

### 12.2 当前项目改造验收建议

每个纳入首期的功能至少应补充以下可观察验收结果，不能只验证 HTTP `2xx`：

1. 创建后列表、详情、统计和审计均能读到同一条数据，且刷新后仍存在。
2. 修改后权限、索引、缓存、搜索和下游问答在定义的最终一致性窗口内收敛。
3. 删除、恢复、永久删除和过期动作有明确状态、确认、幂等键和审计记录。
4. 草稿、已发布快照、运行实例和历史版本之间可追溯，运行失败可重试或解释原因。
5. 个人空间、公司空间、部门和匿名分享主体之间有自动化越权测试，不能依赖前端隐藏菜单。
6. 连接器、模型调用、导出、支付和通知等异步操作必须展示进行中、成功、失败和重试状态。

### 12.3 MCP 与跨空间隔离专项验收

参考站实测的 `knowledge_search` 跨空间泄露属于阻断级风险。当前项目纳入 MCP 或工具出口前，至少需要通过以下验收：

1. 在个人空间和公司空间分别创建同名但内容不同的合成文档，使用同一查询词调用 `knowledge_search`，结果只能来自当前可信 `RequestContext` 的 `workspace_id`。
2. 客户端提交伪造的 `workspace_id`、文档 ID、知识库 ID 或过滤条件时，服务端不得扩大可见范围；忽略客户端空间字段，并记录拒绝或过滤原因。
3. 普通成员、部门成员、被停用成员和匿名分享主体分别调用工具时，结果按资源级权限过滤，不得只依赖工作空间级过滤。
4. 工具调用的输入、召回文档 ID、引用 Chunk、模型输出和审计事件必须带同一空间与主体上下文，禁止使用未带空间维度的缓存键或统计聚合。
5. 任何跨空间命中、引用或错误回显都应使调用失败并触发高优先级安全告警，不得返回部分混合结果。

## 13. API、Worker 与存储影响

### 13.1 API

- 新增文件夹、标签、术语、收藏、回收站、连接器、正文、分享、场景、公开助手、企业知识分类和通知契约。
- 列表接口需要统一分页、排序、筛选和搜索，当前若干页面仍以最多 100 条列表为主，无法直接支撑大规模知识门户。
- 在线编辑必须提供 revision 或 ETag 并发控制，不能把上传文件接口当正文保存接口。
- 公开访问不能复用普通浏览器成员上下文，需要独立匿名/分享主体和最小权限策略。
- 角色、菜单、审计等后端接口可以直接用于新企业管理页，但需增加页面所需的聚合和批量编辑契约。

### 13.2 Worker

- 连接器调度、网页抓取、同步、失败重试和告警。
- 文档格式导入/导出、PDF/DOCX 生成和大文件异步任务。
- 回收站到期永久删除已在 `P6A-02` 实现数据库事实清理、Outbox、对象键隔离、幂等 MinIO 删除和有限重试；真实依赖验收仍未完成。孤儿媒体清理和分享过期清理继续后置。
- AI 推荐标签、脑图、办公 Agent 长任务和可取消运行。
- 通知投递与失败重试。

### 13.3 存储与索引

- 正文结构、编辑快照和媒体对象需要独立于原始上传文件保存。
- 正文发布后才能进入当前可检索版本，草稿不得被普通 RAG 误召回。
- 文件夹移动、标签范围、分享和企业分类变更后需要重算授权或检索范围，但不应复制文档正文。
- 连接器内容必须保留来源、抓取时间、内容摘要和同步版本，支持追溯。
- 公开助手统计应使用聚合事实，不把原始问题、个人标识或文档正文写入指标标签。

## 14. 权限、安全与审计影响

### 14.1 必须坚持的当前边界

1. 前端菜单隐藏仍不构成安全边界，新增页面的每个接口继续由后端 PDP 授权。
2. 文档、文件夹、标签范围、分享、公开助手和连接器均必须绑定 `workspace_id`，禁止跨空间读取。
3. 草稿、已发布正文、原文件、导出文件和索引内容要分别授权，不能用“能看文档列表”推导“能下载原件”。
4. 公司空间的部门可见、密级和字段遮罩继续由服务端执行。
5. 公开链接、密码分享和公开助手必须增加限速、预算、撤销、过期、审计、搜索引擎控制和内容治理。
6. 网页连接器必须防 SSRF、DNS 重绑定、内网访问、重定向绕过和超大响应。
7. 文档 AI 对正文的插入、替换和删除必须提供差异确认、revision 校验和可恢复版本。
8. 个人模型 Key 和 MCP/API Key 不得明文保存、回显或写日志。
9. 回收站永久删除必须与空间保留期、法律保留和备份恢复策略协调，不能由前端直接物理删库。
10. MCP 和内部工具不得信任客户端传入的 `workspace_id`；必须从经过认证的 `RequestContext` 解析空间、成员、角色和资源范围，并在检索、工具执行、缓存、引用和审计链路中持续传递。
11. `knowledge_search`、`document_create`、文档编辑等高风险工具必须执行资源级授权和调用额度检查；跨空间命中时应阻断整次调用并告警。

### 14.2 建议新增权限域

- 文件夹管理；文档正文读取/编辑、历史读取/恢复随 `POST-EDITOR-01` 后置。
- 原文件上传、新版本和授权下载；格式导入、格式导出随 `POST-EDITOR-01` 后置。
- 标签和术语管理。
- 收藏只允许本人管理。
- 分享创建、管理、访问和撤销。
- 连接器定义、凭证、运行和历史读取。
- 场景定义、测试、发布和使用。
- 公开助手发布、暂停、下架、审核和统计读取。
- 企业知识分类、团队知识域和文档审批。
- RAG 命中测试和分析数据读取。

## 15. 建议实施分期

### 15.1 第一期：形成参考站式核心用户体验

目标是让普通用户能够“进入工作台、通过上传文件组织知识、问答并在企业内治理”。第一版不创建或编辑在线正文，也不追求公开生态和实时协作。

建议范围：

1. 新工作台、最近文档和基础统计。
2. 文件夹、标签、收藏、回收站。
3. 上传首版/新版本、移动、解析详情、索引状态、发布/重试和授权下载。
4. AI 助手知识范围、临时附件、快捷指令和会话归档。
5. 企业控制台、邀请链接和成员一体化编辑。
6. 企业知识分类、团队知识域和文档发布审批。
7. 角色权限矩阵和操作审计页。
8. 只读取当前企业知识域的 AI 企业大脑简版。

### 15.2 第二期：完善内容生产与企业门户

1. 网页连接器和定时同步。
2. 术语库和 AI 推荐标签。
3. 场景引擎：Prompt、模型参数、检索参数、基础护栏和预览。
4. RAG 命中测试、知识健康度、低召回和企业问答运营。
5. 工作流/Agent 模板和办公 Agent 门户。

### 15.3 第一版后的独立候选能力

1. `POST-EDITOR-01`：在线正文、富文本编辑、自动保存、历史、格式导入导出和文档 AI 写回，第一版完成后再决定是否建设。
2. `POST-COLLAB-01`：实时协作、在线人数、光标、评论和 @ 提及，必须晚于在线编辑器。
3. 只读链接分享、密码和指定用户分享。
4. 发布问答助手和知识广场。
5. 标准 MCP 外部出口、API Key 管理、Prompt Injection 扫描和联网搜索。
6. 多 Agent 协作、通知中心、AI 记忆和个人模型。
7. 订阅、支付、Token 包和商业化订单。

## 16. 建议优先确认的产品问题

在进入设计和开发前，至少需要由产品负责人确认以下问题：

1. 产品目标是“主要流程类似”还是“页面和功能尽量一比一”。
2. 已确认第一版不做在线文档编辑器；第一版完成后是否启动 `POST-EDITOR-01`，届时重新确认编辑节点和格式范围。
3. 已确认第一版不做多人实时协作，且协作能力必须晚于在线编辑器单独评估。
4. 文档是否需要公开链接；匿名访问是否允许调用 AI。
5. 文件夹、知识库、企业分类和团队空间的领域关系如何定义，避免出现四套重叠层级。
6. 场景、Agent、工作流和发布助手是四个独立对象，还是对同一 Agent 定义的不同产品视图。
7. 企业文档审批审批的是草稿内容、发布动作、分享动作还是全部三类动作。
8. 公开助手和知识广场是否属于当前商业目标；若属于，必须同步建设审核和成本控制。
9. MCP 是否只暴露已发布助手，还是同时暴露知识搜索和受控工具。
10. 套餐页只是展示本地授权，还是要接真实支付和充值。
11. 参考站中的“清除标记”“组织内分享”“训练企业模型”和“AI 记忆”是否真正需要，还是应按当前产品定位重新定义。
12. 当前项目独有的服务发布、灰度、治理控制塔和运行状态页是否继续面向最终用户，还是移入高级管理区。

## 17. 总体决策建议

### 17.1 建议保留并复用

- 当前仓库、模块化单体架构、OpenAPI 契约和统一验证入口。
- 工作空间隔离、组织、RBAC/ABAC、字段权限、菜单发布和审计。
- 知识上传、解析、OCR、索引、RAG、Worker 和对象存储。
- 私有问答、SSE、来源、反馈和取消。
- 工作流审批、Agent 发布、Service、工具执行和治理能力。

### 17.2 建议新增产品层

- 工作台和个人知识管理。
- 场景引擎的结构化用户界面。
- 企业知识门户、权限管理和 AI 企业大脑。
- 第一版完成后按实际价值评估在线文档编辑与文档 AI。
- 后续按商业目标选择公开助手、知识广场、MCP 和支付。

### 17.3 不建议直接照搬

- 不建议照搬参考站所有页面名称和导航层级，应避免“场景、助手、Agent、工作流”概念重复。
- 不建议为了页面相似而绕过当前项目的发布、权限、审计和安全边界。
- 不建议首期同时建设实时协作、公开生态、MCP、支付和多 Agent，这会把范围扩大为多个大型项目。
- 不建议把当前项目的治理控制台能力删除；可以改为高级管理区，对普通用户隐藏。

最终判断：沿用当前项目进行改造，技术底座复用价值高。第一版采用文件型知识管理，不建设在线编辑器，仍属于中大型产品改造；第一版完成后再按使用价值和预算评估 `POST-EDITOR-01`，不需要重新建立代码仓库或重写后端底座。
