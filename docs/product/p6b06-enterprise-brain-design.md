# P6B-06 AI 企业大脑简版设计

## 1. 目标与范围

P6B-06 在现有 Assistant、RAG、团队知识域、模型网关和审计事实之上建设独立的企业大脑产品入口。第一版只支持当前企业内、当前账号获权团队知识域的问答、引用、报告文件、调用统计和近期活动，不读取个人空间、外部公开数据或未授权知识。

本节点不新增第二套模型 Runtime、检索引擎或在线正文模型，也不实施在线文档编辑器、文档 AI 写回、多人实时协作、公开助手和支付能力。真实模型对外开通继续受阶段 5 的质量、成本、隔离与数据政策门禁约束；本地确定性模型只能用于机制和合成数据验收。

## 2. 产品流程

企业成员进入独立的“AI 企业大脑”页面后，只能看到当前可访问的活动团队知识域。选择知识域并新建会话时，服务端记录知识域标识和当前 RAG 策略版本；页面提供企业问答、制度摘要、风险要点、差异分析和报告草稿等快捷任务。

每次提交问题时，服务端重新解析以下交集，而不是复用页面缓存或会话创建时的知识库列表：

```text
活动企业空间
  ∩ 当前活动成员
  ∩ 团队知识域声明的成员/部门范围
  ∩ 团队知识域声明的活动知识库
  ∩ 当前账号 knowledge.document.read 的 PDP 范围
  ∩ 当前密级和字段权限
  = 本次 Run 冻结的可检索范围
```

交集为空、知识域归档、成员停用、部门移除、PDP 不可用或范围解析失败时，创建 Run 必须失败关闭，不得回退到全企业或普通助手的工作空间范围。

## 3. 领域事实

### 3.1 企业大脑会话

企业大脑会话继续复用现有 `Conversation`、`Message`、`AssistantRun`、SSE、引用与反馈事实，但使用独立的 `conversation_kind=enterprise_brain`。会话新增以下不可伪造关系：

- `knowledge_domain_id`：会话固定选择的团队知识域；
- `knowledge_domain_policy_version`：创建会话时看到的策略版本，仅用于展示和变更提示；
- 创建者、工作空间、状态和版本继续沿用现有会话边界。

普通私有助手会话和服务调用会话不得读取或修改企业大脑关系；企业大脑列表也不得混入普通私聊。所有会话仍只对创建者可见，企业管理员不会因为管理权限自动读取成员问答内容。

### 3.2 企业大脑 Run

每次企业问答 Run 除现有运行配置、Agent Release、Route、知识库集合和 Trace 外，还冻结：

- `knowledge_domain_id`；
- `knowledge_domain_policy_version`；
- 本次重新鉴权后的 `knowledge_base_ids`；
- 当前文档 PDP 决策版本、密级和字段遮罩仍由检索计划冻结。

Run 一旦排队，上述范围不可修改。执行器在检索阶段继续重新执行文档级 PDP；如果策略版本、字段遮罩或当前授权与已存在检索计划不一致，拒绝沿用旧候选。知识域在排队前已经失败关闭，文档权限在执行时再次失败关闭，形成两层防线。

### 3.3 报告文件

报告不是在线文档，不写入知识库正文，也不自动发布。第一版报告文件由用户基于一条已完成、仍可读取来源的企业大脑回答显式生成，保存为独立的不可变 Markdown 文件事实：

- 冻结工作空间、知识域、会话、回答消息、Run、模板、标题和生成时间；
- 冻结报告正文摘要、内容 SHA-256 和引用数量；
- 只允许创建者在当前企业成员仍有效且仍具备报告读取权限时查看或下载；
- 下载由服务端返回附件内容，不暴露对象键或内部存储定位；
- 来源撤权后报告正文仍按历史产物保留，但来源详情必须重新鉴权，不能借报告反查已撤权文档；
- 报告创建、审计和 Outbox 在同一事务提交，幂等键阻止重复生成。

支持的固定模板为 `briefing`（企业简报）、`risk_review`（风险审阅）和 `comparison`（差异分析）。模板只约束报告结构，不建立可编辑正文、自动保存或 AI 写回能力。

## 4. 聚合读模型

企业大脑页面使用单一聚合接口返回以下低敏事实，避免前端拼接多个时间点的内部管理接口：

- 当前企业名称和生成时间；
- 当前账号可访问的活动知识域、当前策略版本、RAG 模式和有效知识库数量；
- 当前账号自己的企业大脑活动/已归档会话；
- 当前账号生成的报告文件；
- 最近 30 天调用统计：总 Run、完成、失败、取消、输入/输出 Token 和估算成本；
- 当前账号最近活动：会话创建、问答完成/失败、报告生成与会话归档。

统计时间窗固定为接口响应中的 `[window_started_at, window_ended_at)`。Run 状态来源于 `assistant_runs`，Token 和估算成本来源于相同 `trace_id` 关联的 `model_invocations`；两者属于最终一致读模型，响应必须返回生成时间并明确可能存在短暂延迟。近期活动不返回问题正文、回答正文、报告正文、对象键、凭证或自由审计属性。

## 5. API 与权限

新增独立页面 `/workspace/enterprise-brain`，建议使用以下权限：

| 权限码 | 资源 | 作用 |
| --- | --- | --- |
| `enterprise.brain.access` | `page` | 访问企业大脑页面 |
| `enterprise.brain.read` | `enterprise_brain` | 读取当前账号的聚合、会话、统计和活动 |
| `enterprise.brain.conversation.create` | `team_knowledge_domain` | 在获权知识域中创建会话 |
| `enterprise.brain.message.create` | `conversation` | 在自己的企业大脑会话中提问 |
| `enterprise.brain.conversation.archive` | `conversation` | 归档自己的企业大脑会话 |
| `enterprise.brain.report.create` | `assistant_message` | 从自己的已完成回答生成报告 |
| `enterprise.brain.report.read` | `enterprise_brain_report` | 查看和下载自己的报告 |

入口必须使用可信 `RequestContext`，路径 `workspace_id` 与 Header 空间必须一致。知识域创建会话时先执行知识域资源级授权；会话、消息和报告再执行目标资源级授权与创建者校验。API Key 不开放企业大脑产品入口。

建议接口如下：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/workspaces/{workspace_id}/enterprise-brain` | 页面聚合快照 |
| `POST` | `/api/v1/workspaces/{workspace_id}/enterprise-brain/conversations` | 选择知识域创建会话 |
| `POST` | `/api/v1/workspaces/{workspace_id}/enterprise-brain/conversations/{conversation_id}/messages` | 重新解析知识域范围并排队 Run |
| `POST` | `/api/v1/workspaces/{workspace_id}/enterprise-brain/conversations/{conversation_id}/archive` | 归档会话 |
| `POST` | `/api/v1/workspaces/{workspace_id}/enterprise-brain/reports` | 从已完成回答生成报告文件 |
| `GET` | `/api/v1/workspaces/{workspace_id}/enterprise-brain/reports/{report_id}` | 查看报告元数据和正文 |
| `GET` | `/api/v1/workspaces/{workspace_id}/enterprise-brain/reports/{report_id}/download` | 下载 Markdown 报告 |

既有消息、Run、SSE、来源与反馈协议在验证企业大脑会话归属后复用，不复制另一套流式协议。

## 6. 事务、并发与事件

- 创建会话时，知识域当前范围解析、会话事实、审计和 Outbox 在一个数据库事务内完成；
- 提交问题时重新锁定会话，重新解析知识域当前范围，并把用户消息、助手占位消息、Run、用量、审计和 Outbox 一次提交；
- 同一会话只允许一个 `queued/running` Run，沿用现有唯一约束；
- 报告以 `workspace_id + created_by_account_id + idempotency_key` 幂等，键绑定不同回答或模板时返回稳定冲突；
- 会话知识域、Run 知识域/范围和报告来源关系由数据库约束及不可变触发器保护；
- Worker 重试仍复用 Run 状态机和 SSE 游标，不创建第二套任务协议。

## 7. 页面结构

页面采用“企业情报台”而不是普通聊天页的视觉结构：

1. 顶部显示当前企业、30 天调用摘要、成功率和数据更新时间；
2. 左侧知识域轨道展示可访问范围、RAG 策略和有效知识库数；
3. 中央问答工作区复用消息、流式状态、取消、引用和反馈组件，但不显示普通助手的知识库/标签及临时附件选择；
4. 快捷任务以明确模板卡片预填问题，不直接调用模型；
5. 右侧或移动端下方展示近期活动和报告文件；
6. 个人空间显示“不启用 AI 企业大脑”，不显示伪造的空企业数据；
7. 桌面和移动均不得产生页面级横向滚动，宽表或长引用仅在局部容器滚动。

页面必须明确展示阶段 5 门禁状态：本地合成机制可用不等于真实供应商已经通过质量、成本和数据政策验收。

## 8. 验收矩阵

### 8.1 自动化验收

- 企业成员仅能列出自己当前获权的活动知识域；
- 个人空间、另一企业、停用成员和范围外成员访问失败关闭；
- 知识域无知识库、PDP 交集为空或策略依赖异常时不得创建 Run；
- 会话创建后移除成员、部门或知识库，再次提问必须失败；
- Run 冻结知识域、策略版本和知识库范围，后续更新不能改写历史 Run；
- 引用继续执行当前文档版本和授权复核，跨空间来源不可见；
- 报告只允许从自己的已完成企业大脑回答生成，幂等重放返回同一事实；
- 报告下载不暴露对象键，来源撤权后不能通过报告读取来源详情；
- 聚合统计只计算当前工作空间与企业大脑 Run，时间窗和最终一致性字段准确；
- Migration 支持空库、存量库升级和安全往返，生命周期 Registry 覆盖报告事实；
- OpenAPI、生成类型、资源 Registry、菜单绑定、mypy strict、Ruff、pytest、前端测试和生产构建通过。

### 8.2 真实运行验收

使用明确标记的全合成企业、成员、部门、知识域、知识库和文档完成正式 HTTP 登录与空间切换，实际创建企业大脑会话、执行快捷任务和普通提问、查看引用、生成并下载报告、归档会话，并验证调用统计及近期活动更新。

验收过程中实际移除知识域成员或收缩知识库范围，确认旧页面再次提问被拒绝且没有范围回退；以另一空间上下文访问会话、引用和报告均被拒绝。桌面 `1440×900` 与移动 `390×844` 验证页面无全局横向溢出，浏览器 warning/error 为 0。

## 9. 实现顺序

1. 增加企业大脑领域模型、知识域范围查询端口、会话/Run 关系和 Migration；
2. 实现创建会话、重新鉴权提问、归档及既有 SSE/引用复用；
3. 实现不可变报告文件、查看与下载；
4. 实现聚合统计、近期活动和独立页面；
5. 完成 PostgreSQL、HTTP、Migration、跨空间、撤权传播、桌面/移动和完整门禁验收；
6. 同步阶段文档并形成独立 `P6B-06` Git 提交。

## 10. 实现与验证记录

P6B-06 已按本设计完成代码、真实运行和最终统一门禁验证，独立提交完成前节点仍保持“进行中”。实现继续复用现有 Assistant、SSE、检索计划、模型网关、反馈和引用事实，没有建立第二套模型或检索 Runtime。

### 10.1 已实现边界

- 企业大脑会话以 `conversation_kind='enterprise_brain'` 与普通助手会话隔离，并冻结 `knowledge_domain_id` 和创建时的 RAG 策略版本。
- 每次提问均重新验证企业成员、团队知识域和资源级权限，解析当前有效知识库交集后冻结到 Run；空范围、知识域失效或策略依赖失败时关闭失败，不回退到全企业检索。
- Run 继续通过既有模型网关、SSE、取消、来源复核和反馈链路执行；引用只来自服务端重新授权后的 Retrieval Evidence。
- 报告是用户从已完成回答显式生成的不可变 Markdown 事实，冻结模板、正文、SHA-256 和引用数量。引用数量取自当前授权的 Retrieval Evidence，不解析或信任模型回答正文中的引用标记。
- 页面聚合当前账号自己的知识域、活动/归档会话、近 30 天调用统计、近期活动和报告；归档会话只读，快捷任务只预填问题，不自动触发模型调用。
- 全局应用壳层通过低敏 `GET /api/v1/platform/administration` 判断平台管理员资格。普通企业成员获得 `is_platform_administrator=false`，不会为了菜单裁剪请求管理员业务列表；`/api/v1/platform/model-providers` 对普通成员仍返回 403，业务安全边界未降低。
