> 调研范围：个人空间、公司空间“西西科技”、知识生产、AI 问答、场景、工作流、RAG 和企业治理

## 1. 文档用途

这是一份可以直接交给产品、设计、前后端和测试团队阅读的参考文档。它回答四个问题：

1. 产品有哪些空间、页面、实体和状态。
2. 每个页面可执行哪些增删改查（CRUD）和业务流程动作。
3. 在有合成数据时，用户从创建到使用的完整链路是什么。
4. 开发同类产品时，哪些规则必须落到服务端，哪些能力可以分期建设。

文档中的“已实测”来自当前登录会话中的真实页面和实际操作；“入口已见”表示看到了页面、字段或按钮，但没有提交可能改变数据或访问边界的最终动作；“待验证”表示当前账号、数据或安全边界不足以得出结论。

本文件是新建的独立文件，不覆盖上一轮的功能差距分析文档。上一轮文档可作为当前项目映射和工程量估算的补充材料。

## 2. 调研边界与数据策略

### 2.1 账号和隐私边界

- 使用当前已登录的测试账号和公司空间进行页面走查。
- 文档不保存账号、密码、Cookie、Token、API Key、支付信息、邀请链接或真实成员资料。
- 本轮创建的内容均为虚构产品资料，不上传本地文件，不调用真实外部服务，不购买套餐，不邀请真实成员。
- 不删除、清空、永久删除已有数据；不公开发布助手；不保存密码分享的访问密码。
- 页面中原本存在的内容标记为“账号已有数据”，不能误认为本轮创建。

### 2.2 验证口径

| 标记 | 含义 |
| --- | --- |
| 已实测 | 已创建或修改合成数据，并在后续页面看到持久化结果 |
| 入口已见 | 已看到入口、表单或按钮，但没有提交最终动作 |
| 空状态已见 | 页面能打开，但没有可用于验证的业务数据 |
| 有风险 | 实际行为与用户预期或常见空间隔离规则不一致 |
| 未执行 | 会产生破坏性、对外访问、支付或真实外部副作用的动作 |

## 3. 产品定位与核心对象

JitKnow 可以理解为“知识生产工作台 + 企业知识门户 + AI 应用配置平台”。个人空间侧重个人收集、编辑、组织和问答；公司空间在通用能力之上增加企业分类、团队知识域、成员治理、权限和企业问答。

### 3.1 空间层级

```text
用户
├─ 个人空间
│  ├─ 文件夹 / 文档 / 标签 / 术语 / 连接器
│  ├─ 场景 / AI 助手 / 工作流 / 办公 Agent
│  └─ 收藏 / 回收站 / RAG 评估 / 个人设置
└─ 公司空间
   ├─ 企业资料 / 成员 / 部门 / 角色权限 / 审计
   ├─ 企业分类 / 团队空间 / 企业文档
   └─ AI 企业大脑 / 企业统计
```

所有可持久化对象都应绑定 `workspace_id`。用户、公司、部门和匿名分享主体只是访问主体，不能成为跨空间读取的替代条件。

### 3.2 主要实体

| 实体 | 关键字段 | 典型状态 |
| --- | --- | --- |
| Workspace | `id`、`type`、`name`、`status` | active、suspended |
| Folder/Knowledge Space | `id`、`workspace_id`、`parent_id`、`rag_enabled` | active、archived |
| Document | `id`、`folder_id`、`title`、`source_type`、`owner_id` | draft、indexing、indexed、failed、deleted |
| Document Version | `document_id`、`version`、`content`、`created_by` | draft、current、superseded |
| Chunk | `document_id`、`content`、`embedding_status`、`enabled` | pending、indexed、disabled、failed |
| Tag | `workspace_id`、`name`、`color` | active、deleted |
| Term | `standard`、`aliases`、`enabled` | enabled、disabled |
| Web Connector | `urls`、`schedule`、`selector`、`folder_id` | active、paused、syncing、failed |
| Scenario | `name`、`knowledge_scope`、`style`、`model_policy` | draft、applied、archived |
| Assistant | `scenario_id`、`knowledge_scope`、`visibility` | draft、published、paused、expired |
| Workflow Agent | `definition`、`version`、`trigger` | draft、validated、published、disabled |
| Share Link | `document_id`、`token_hash`、`access_policy`、`expires_at` | active、expired、revoked |
| Enterprise Category | `workspace_id`、`name`、`description`、`visibility` | active、archived |
| Audit Event | `workspace_id`、`actor`、`action`、`resource`、`created_at` | immutable |

## 4. 全局导航与空间切换

### 4.1 个人空间导航

工作台、知识库、AI 助手、场景引擎、AI 问答助手、AI 工作流、办公 Agent、MCP 工具、知识广场、收藏、回收站、RAG 评估、升级套餐、设置。

### 4.2 公司空间导航

公司空间保留通用导航，并增加企业控制台、团队管理、企业知识库、权限管理、AI 企业大脑。页面标题、文件夹树、问答范围、统计和权限都必须跟随当前空间切换。

### 4.3 空间切换验收

1. 打开空间选择器，列出当前用户可访问的个人空间和公司空间。
2. 切换后刷新页面，导航、列表、统计和检索上下文全部更新。
3. 在个人空间创建同名文档后，公司空间搜索和 RAG 不得返回该文档。
4. 退出公司、成员停用或权限回收后，旧页面和旧会话请求均应在服务端重新校验。

## 5. 个人空间功能说明

### 5.1 工作台

**页面目标**：让用户从一个页面开始创建知识、打开最近内容或发起 AI 任务。

| 功能 | CRUD/流程 | 页面要求 |
| --- | --- | --- |
| 全局搜索 | R | 支持按名称或内容搜索，显示类型、空间、更新时间和高亮 |
| 快速新建 | C | 新建文档、新建表格，创建后进入编辑器 |
| 文件导入 | C、P | 选择格式、目标文件夹和是否启用 RAG，显示解析进度 |
| 最近内容 | R | 按最近编辑时间排序，可直接打开文档 |
| AI 快捷入口 | P | 总结、续写、翻译、提取要点、润色、问答、代码解释、脑图 |
| 统计卡片 | R | 文档数、知识分类、AI 调用、收藏数，明确统计时间窗 |

### 5.2 知识库与文件夹

#### 5.2.1 文件夹 CRUD

**创建**：点击“新建文件夹”，填写名称、父文件夹和 RAG 开关。创建“研发资料”后，列表显示“已启用 RAG”和 1 个文档。

**读取**：左侧文件夹树显示全部文档、文件夹、RAG 状态和文档数量；主区支持列表视图/卡片视图、名称/内容搜索、修改时间/大小排序。

**更新**：重命名、移动、切换 RAG。关闭 RAG 时应说明已索引内容是否保留、是否停止新索引；移动后需重新计算继承的权限和知识范围。

**删除**：进入回收站而不是直接物理删除，递归处理文档、Chunk、附件和索引任务。最终永久删除需要单独确认和审计。

#### 5.2.2 文档列表和操作菜单

列表至少展示文档名、索引片段数、标签、来源格式、最后编辑时间、文件夹、大小和协作状态。单文档“更多操作”包含：

- 编辑：进入在线编辑器。
- 解析详情：查看字符数、Chunk、索引状态、来源和预览。
- 清除标记：清理解析或同步产生的状态标记。
- 分享：创建链接、设置密码/有效期/指定用户。
- 移动到：选择其他文件夹。
- 标签：应用、移除或新建标签。
- AI 推荐标签：根据正文生成建议，用户确认后写入。
- 下载/导出：原文件或 JSON、HTML、DOCX、PDF、Markdown。
- 收藏：写入收藏夹。
- 删除：移入回收站。

本轮对“产品路线图”执行了收藏，收藏页显示“收藏于 2 分钟前 · 知识库”，并提供分享和取消收藏。

### 5.3 在线文档编辑器

#### 5.3.1 创建和保存

1. 在文件夹中点击新建，输入标题后进入编辑器。
2. 正文以编辑器状态保存，页面应显示保存中、已保存、冲突或失败。
3. 返回知识库后更新文档大小、最后编辑时间和索引状态。
4. RAG 文件夹中的正文保存成功后异步分块、向量化并显示“已索引 N 个片段”。

本轮“产品路线图”正文为：

```text
产品路线图
第一阶段：完成知识库、文档编辑和基础问答。
第二阶段：增加团队协作、审批和企业知识门户。
第三阶段：完善公开助手、工作流和运营分析。
```

返回知识库后显示 DOCX、667 B、已索引 1 个片段、所在文件夹“研发资料”、协作状态“仅自己”。

#### 5.3.2 编辑能力

工具栏包括段落、标题、字体、字号、加粗、斜体、下划线、删除线、文字/背景颜色、对齐、无序/有序/任务列表、缩进、间距、行内代码、上下标、搜索替换。

插入组件包括图片、音频、视频、内嵌网页、附件、电子签名、表格、Excel、图表、思维导图、LaTeX、链接、引用、JavaScript、分隔线和分栏。

右侧或浮层 AI 能力包括聊天、总结、脑图、翻译和结构化编辑。结构化编辑至少支持插入、替换、删除、设置标题、插入表格和摘要；应用前要展示差异预览并支持撤销。

#### 5.3.3 版本、导入、导出和分享

| 能力 | 需求 |
| --- | --- |
| 版本 | 自动保存版本、查看历史、恢复为新版本，恢复需保留审计记录 |
| 导入 | 支持 DOCX、TXT、MD、PDF、XLSX、XLS、PPTX，单文件上限 20 MB |
| 导出 | JSON、HTML、DOCX、PDF、Markdown，异步导出需反馈成功/失败 |
| 分享 | 邀请协作、链接分享、微信分享、分享海报 |
| 访问控制 | 任何人、密码、指定用户；支持有效期、不被搜索引擎索引 |
| 协作 | 当前页面显示在线人数；组织内分享在参考站标记为即将上线 |

不应把“复制链接成功”当作分享安全验证。开发时需测试撤销、过期、密码错误限速、指定用户离职和搜索引擎控制。

### 5.4 标签、术语和网页连接器

#### 标签

标签支持新建、查询、筛选、批量应用、移除和删除。标签删除不应删除文档，只移除关联。已创建“路线规划”并应用到“产品路线图”。

#### 术语库

术语包含标准术语、别名、启停状态和查询扩展。已创建标准术语“知识空间”，别名为“知识库、知识域”；页面提示“术语「知识空间」已创建”。

#### 网页连接器

表单包括名称、多个 URL、目标文件夹、同步周期、Cron 表达式、CSS 选择器、启用/停用。同步过程为“配置 → 手动同步/定时同步 → 抓取 → 解析 → 新建或更新文档 → RAG 索引”。同一 URL 再次同步应幂等更新，不重复创建文档；外部站点失败应提供重试和错误详情。

### 5.5 AI 助手与 AI 问答

#### AI 助手

入口支持选择知识库、文件夹、标签或场景，发起私有会话，上传临时附件，使用快捷指令并查看引用。回答区提供复制、有用、无用、分享和“改进并入库”。会话应支持新建、历史读取、重命名、删除、取消生成和反馈。

#### 真实问答流程

公司空间中使用账号已有的“客户支持助手”发起问题：

> 请根据客户服务指南，概括产品支持流程、响应时效和升级条件。

实际回答引用“客户服务指南”和“客户支持知识空间”，并给出：确认客户名称/版本/现象、检索知识库、无法解决时建立工单；一般咨询 4 个工作小时内首次响应，紧急故障 30 分钟内响应并持续同步。点击“有用”后按钮变为 active，页面提示“感谢反馈！”。

这条链路证明了问答生成、引用、反馈和会话持久化是四个独立状态，不能只返回一段文本。

#### AI 问答助手发布表单

发布助手前应配置助手名称、头像、简介、关联知识库/场景、快捷回复、公开方式（任何人、密码、指定用户）、有效期和内容治理。发布是改变匿名访问边界的动作，必须显示最终权限、过期时间和撤销入口；本轮未点击“立即发布”。

### 5.6 场景引擎

已创建自定义场景“项目顾问”，使用“知识讲解模式”模板。基础配置页面包含：

- 场景名称、关联知识库。
- 回答风格：简洁直接、详细完整、步骤化、故事化。
- 输出格式：分步骤说明、代码示例、图文结合、注意事项、相关链接、延伸阅读。
- 专业度、热情度、正式度滑杆。
- 开场白、结束语。
- 恢复默认、保存为草稿、保存并应用。

高级设置还包括提示词工程、Few-shot 示例、Temperature、Top-P、最大 Token、模型、语义/关键词/混合检索、相似度阈值、Top-K、Rerank、查询改写、上下文记忆轮数、长期记忆、用户画像、会话隔离、敏感词、越狱防护、话题限定、PII 脱敏和 Fallback 策略。

建议将场景建模为不可变版本：草稿可编辑，应用时生成版本快照，问答和公开助手只引用已应用版本。

### 5.7 AI 工作流

模板库包含“默认 RAG 助手”等模板。点击模板后创建了 `未命名 Agent` 草稿，列表统计变为总数 2、已发布 1、草稿 1，草稿信息为 `v1.0.0`、`Office RAG`、7 个节点。

节点包括：输入审核/安全审核、知识检索、检索充分性 gate、生成回复/LLM 调用、反思校验/LLM 调用、查询重写、结束。

实际尝试重命名为“知识问答助手”并保存时，页面提示“存在不可达节点：queryRewrite”，状态保持“未保存”，发布按钮禁用。返回时会弹出“放弃未保存的更改？”，可继续编辑或放弃离开；放弃后草稿仍保留为“未命名 Agent”。

因此工作流必须有：节点图校验、不可达节点提示、保存前错误定位、版本草稿、试运行、发布、停用、运行记录和重试。不能把“模板打开成功”视为模板可发布。

### 5.8 办公 Agent、MCP 工具和知识广场

**办公 Agent**：以已发布工作流为能力来源，提供场景卡片、开始对话、快捷任务、历史会话、文件输入和 Word 导出。导出前应校验会话确实生成了可导出的正文。

**MCP 工具**：工具目录展示名称、描述、参数、示例、鉴权状态和额度；调试区支持 JSON 输入、运行、取消、结果和错误。`knowledge_search` 必须从可信请求上下文取得空间和权限，禁止由客户端参数覆盖。

**知识广场**：展示公开助手卡片、作者、头像、知识库、场景、标签、使用/对话入口和排行。公开内容需要审核、撤销、举报、限流、配额和匿名访问审计。本轮没有公开发布助手。

### 5.9 收藏、回收站、RAG 评估、套餐和设置

**收藏**：列表提供搜索、最近收藏排序、打开、分享和取消收藏。已验证“产品路线图”出现在“我的收藏”，页面显示“共收藏 1 个文档”。

**回收站**：展示删除时间、原文件夹、恢复和永久删除；页面说明通常保留 30 天后自动清理。恢复应回到原文件夹并重算索引，永久删除必须二次确认。本轮未删除任何文档。

**RAG 评估**：命中测试支持查询、语义/关键词/混合（Hybrid/RRF）、Top-K、Rerank、查询改写，展示召回 Chunk、分数、策略详情和被过滤项；分析页展示查询量、平均响应时间、点赞率、策略分布、Top 命中和低召回查询；知识库概览展示 RAG 文件夹、文档数、Chunk 数、警告和健康度。

**升级套餐**：可查看免费版、个人月付、个人年付、配额和功能差异，付款前必须展示金额、周期和退款规则。本轮只进入支付弹层，未付款、未保存支付信息。

**设置**：包含账号资料、密码/安全、通知、模型和记忆等入口。真实个人资料和凭证不应写入产品文档或测试数据。

## 6. 公司空间功能说明

公司空间继承个人空间通用页面，但所有列表、问答、统计和权限增加公司工作空间边界。

### 6.1 企业控制台

首页聚合公司名称、成员数、文档数、知识增长、AI 调用、热门问题、最近活动和套餐配额。统计必须定义时间窗、时区、事件口径和最终一致性延迟。

### 6.2 团队管理

成员页支持邀请链接、添加成员、添加部门、搜索、角色筛选和编辑成员。成员编辑字段包括角色、部门、职位、部门管理员；角色至少包含超级管理员、管理员、普通成员。邀请链接有有效期，重新生成会使旧链接失效。本轮没有生成或发送邀请，也没有新增真实成员。

### 6.3 企业知识库

#### 企业分类

分类字段包括名称、描述、公开/私有访问策略、文档列表、创建人、更新时间和审批开关。已创建“项目资料”，描述为“记录项目目标、里程碑和交付说明”，创建提示成功，卡片显示“暂无文档、公开”；创建“研发项目概览”后计数变为 1 个文档。

企业知识库中的新建文档目前更像门户/元数据管理：卡片显示“研发项目概览”“未知 · 刚刚”，点击标题没有进入与个人空间相同的正文编辑器。开发时应明确企业文档是否复用正文编辑器，或定义“企业资料卡”和“可编辑文档”两类对象，避免入口语义不一致。

#### 团队空间

团队空间字段包括名称、空间类型（团队空间/企业知识库）、团队或项目归属、RAG 开关和成员范围。尝试创建“研发空间”时页面提示“【研发空间】创建成功”，但刷新后列表仍只有原有“客户支持知识空间”和“团队空间”，没有显示“研发空间”。这是需要优先修复或补充成功判定的持久化/刷新问题，不能仅以 toast 作为成功依据。

### 6.4 权限管理和审计

权限页提供超级管理员、管理员、普通成员和自定义角色，使用权限矩阵配置知识库、文档、成员、分享、导出、问答、场景、工作流、审计等动作。矩阵保存必须校验角色不能授予超过自身范围的权限，并记录变更前后差异。

审计日志至少记录 actor、workspace、action、resource、result、IP/设备摘要、时间和 request id，支持搜索、筛选、详情和导出。导出必须反馈进行中、成功、失败和下载有效期。本轮未保存新的角色矩阵，未导出审计日志。

### 6.5 AI 企业大脑

企业大脑支持选择一个或多个公司知识空间，输入问题，返回带来源的企业问答，并展示运营统计和报告模板。知识空间必须来自当前公司，引用文档必须可追溯到分类/团队空间和版本。

公司空间中对已有“客户支持助手”的实际问答已引用公司知识库文档“客户服务指南”。这证明公司问答需要知识范围、引用、反馈和会话审计，而不是简单复用个人问答接口。

## 7. 端到端流程和验收标准

### 7.1 个人文档入库到问答

```text
创建文件夹 → 开启 RAG → 新建文档 → 编辑与自动保存
→ 分块与向量化 → 知识库列表显示索引状态
→ AI 助手选择知识范围 → 问答生成引用
→ 用户反馈 → 反馈统计与改进任务
```

验收：文档正文、当前版本、Chunk、索引状态、引用和反馈都能在刷新后读取；索引失败可重试；未完成索引的文档不能被标记为健康。

### 7.2 企业分类到企业问答

```text
创建企业分类 → 创建或关联文档 → 配置成员/角色范围
→ 发布可用版本 → 进入企业知识空间并启用 RAG
→ 企业大脑选择知识源 → 问答引用公司文档
```

验收：个人文档不出现在企业召回；成员权限变化即时影响新请求；匿名或无权用户只能看到公开内容。

### 7.3 场景配置到助手应用

```text
选择模板 → 填写风格/格式/模型/检索/护栏
→ 保存草稿 → 效果预览 → 应用版本
→ AI 助手引用已应用场景 → 反馈与版本指标
```

验收：草稿修改不影响线上版本；参数越界有明确错误；应用失败可恢复；回答可以反查使用的场景版本。

### 7.4 工作流模板到发布

```text
选择模板 → 节点编辑与连线 → 图校验
→ 保存草稿 → 试运行 → 查看节点运行明细
→ 发布不可变版本 → 配置触发器 → 运行/停用/回滚
```

验收：不可达节点、无结束节点、循环无退出和缺少必填参数均阻断发布；运行记录包含输入摘要、节点状态、耗时、错误和重试；Webhook/Cron/事件触发均有鉴权和幂等键。

## 8. 状态、权限和 CRUD 矩阵

### 8.1 文档状态机

```text
draft → saving → current → indexing → indexed
                 └──────→ save_failed
indexing → index_failed → indexing（重试）
current/indexed → deleted → restored → indexing
```

文档删除只是进入回收站；永久删除还要清理对象存储、版本、Chunk、向量和分享授权。版本恢复应创建新版本，不覆盖历史事实。

### 8.2 动作权限矩阵（建议基线）

| 资源/动作 | 所有者 | 管理员 | 普通成员 | 匿名分享主体 |
| --- | --- | --- | --- | --- |
| 个人文档创建/编辑 | √ | 不适用 | 不适用 | × |
| 公司文档读取 | √ | √ | 按分类授权 | 仅公开链接 |
| 公司文档编辑 | √ | 按权限 | 按权限 | × |
| 成员和部门管理 | √ | 按管理权限 | × | × |
| 角色权限矩阵 | √ | 按授权 | × | × |
| 场景草稿 | √ | 按授权 | 按授权 | × |
| 工作流发布 | √ | 按授权/审批 | ×或按授权 | × |
| RAG 评估 | √ | √ | 按知识范围 | × |
| 审计日志 | √ | 按授权 | × | × |
| 分享撤销 | 创建者/管理员 | 按授权 | 按授权 | × |

前端菜单隐藏不是安全边界。每个 API 都要从可信 `RequestContext` 取得当前用户、空间、角色和资源范围，并在查询、写入、导出、工具调用和异步任务中重复校验。

## 9. 实际发现的问题与开发风险

### 9.1 企业团队空间创建成功但刷新后消失（高优先级）

创建“研发空间”得到成功提示，但刷新列表后不存在。可能原因包括创建接口异步落库、列表接口过滤错误、类型映射错误或缓存未失效。产品上应以列表读取到持久化实体作为成功标准，并提供失败状态和重试。

### 9.2 公司 RAG 评估和概览出现个人空间数据（严重安全风险）

公司空间 RAG 查询“产品支持流程和紧急故障的响应时效”时，结果出现个人文档“产品路线图”和个人文件夹“研发资料”；知识库概览也同时显示个人 RAG 文件夹。该现象不是设计预期，应视为疑似 workspace 绑定或数据隔离缺陷。

修复要求：

1. 检索、统计、缓存键、分析任务和引用记录强制包含 `workspace_id`。
2. 客户端不能通过请求参数覆盖服务端的可信空间上下文。
3. 增加个人/公司同词不同文档、普通成员、停用成员、匿名链接和 MCP 调用的越权测试。
4. 在发布前对历史索引、向量库、异步任务和聚合缓存做隔离回归。

### 9.3 工作流默认模板存在不可达节点

默认 RAG 模板打开后，保存提示 `queryRewrite` 不可达，导致改名、描述保存和发布被阻断。模板发布前应由系统自检，错误应定位到节点并提供自动修复或清晰的连线指引。

### 9.4 企业文档入口和个人编辑器语义不一致

企业文档创建后能在卡片中看到元数据，但标题点击没有进入个人空间式正文编辑器。需要在 PRD 中确定企业文档的正文能力、审批版本和编辑入口，不能让用户误以为“创建成功”就等于“可以编辑”。

### 9.5 统计和历史数据必须有空间边界

企业大脑、RAG 分析、MCP 工具和热门问题聚合都可能跨空间。除主查询外，历史记录、推荐、缓存、报表和导出同样需要空间过滤和权限快照。

## 10. 研发落地建议

### 10.1 推荐 MVP（第一期）

1. 个人/公司空间切换和统一 `workspace_id` 上下文。
2. 文件夹、文档、标签、收藏、回收站和搜索。
3. Markdown/DOCX 在线编辑、自动保存、版本和基础导出。
4. RAG 入库、索引状态、Chunk 详情和基础命中测试。
5. AI 问答、引用、反馈、取消生成和会话历史。
6. 场景基础配置：Prompt、模型、检索参数、输出风格和护栏。
7. 企业分类、团队知识域、成员角色和最小审计日志。

### 10.2 第二期

1. 密码/指定用户/只读链接分享和访问审计。
2. 网页连接器、定时同步和失败重试。
3. 工作流模板、低代码画布、试运行、发布和运行明细。
4. 办公 Agent 门户、文件输入和可靠导出。
5. RAG 分析、低召回查询、健康度和运营报表。
6. 企业大脑多知识空间联检、审批和部门范围。

### 10.3 第三期

1. 公开助手、知识广场、审核、举报和匿名配额。
2. 实时协作、评论、组织内分享和分享海报。
3. MCP 外部连接器、工具市场和更细粒度工具权限。
4. 个人模型、长期记忆、通知中心和高级运营分析。

不建议在第一期直接照搬所有导航名称。应先统一“文档、知识空间、场景、助手、工作流、Agent”的领域词汇，避免同一个 Agent 被多个页面重复建模。

## 11. 建议的接口与任务边界

### 11.1 API 领域

- `workspace`：空间列表、切换、成员、部门和权限上下文。
- `knowledge`：文件夹、文档、版本、Chunk、标签、术语、收藏和回收站。
- `connector`：网页源、同步计划、同步运行和失败重试。
- `assistant`：会话、消息、引用、反馈、发布和访问控制。
- `scenario`：草稿、版本、预览、应用和回滚。
- `workflow`：定义、校验、运行、版本、发布、触发器和审计。
- `enterprise`：分类、团队知识域、审批、统计和企业问答。

契约只传输稳定 DTO，不暴露 ORM、内部异常类或模型供应商对象。所有异步动作返回任务 ID、状态、错误码和重试建议。

### 11.2 Worker 任务

- 文档解析、格式转换、OCR、分块、Embedding 和索引重建。
- 网页同步、去重、内容变更检测和失败重试。
- DOCX/PDF/HTML/Markdown 导出。
- 回收站到期清理、孤儿附件清理和分享链接过期。
- RAG 分析聚合、低召回检测和企业统计。

每个 Worker 任务都要带 `workspace_id`、资源版本和幂等键；任务执行时再次校验资源是否仍可见，禁止使用过期权限快照写入其他空间。

- [ ] 企业成员、部门、角色、审批和审计形成可追溯闭环。

## 13. 调研数据保留与清理说明

本轮没有执行删除、清空回收站、永久删除、公开发布、发送邀请、修改真实资料、购买套餐或调用真实外部服务。为便于复核，合成数据暂保留在当前登录账号中，后续如需清理，应先逐项确认要保留的对象，再在回收站流程中处理，不直接执行批量删除。

## 14. 待产品负责人确认的问题

1. 企业分类和团队空间是否是同一知识域实体的两种视图，还是必须独立建模。
2. 企业文档是否必须复用个人在线编辑器，审批针对草稿、版本还是发布动作。
3. “场景、AI 助手、工作流、办公 Agent”是四个实体还是同一 Agent 的四种产品视图。
4. 首期是否需要密码分享、指定用户分享和组织内分享。
5. 公开助手和知识广场是否属于首期范围，匿名访问的配额和审核由谁负责。
6. RAG 评估是管理员能力还是普通成员也可使用，分析数据保留多久。
7. 企业统计以调用事件、消息事件还是成本事件为准。
8. 个人空间和公司空间是否允许同一用户创建同名对象，搜索结果如何显示空间。

## 15. 结论

JitKnow 的核心产品闭环是“知识创建/导入 → 编辑和组织 → RAG 索引 → AI 问答/应用 → 反馈和运营”，公司空间再叠加“分类/团队知识域 → 成员权限 → 审批审计 → 企业大脑”。

如果目标是开发同类产品，建议先以本文第 10 章的 MVP 为范围，先把空间隔离、文档正文、索引状态、引用反馈和企业权限做成可验证闭环，再逐步增加公开生态、实时协作和高级工作流。本文可以继续转换为：

- 面向评审的 PRD（补充用户故事、非功能需求、埋点和原型链接）。
- 面向设计的页面原型清单（补充页面状态、组件、交互和异常态）。
- 面向研发的任务拆解（补充 API 契约、数据库迁移、Worker、测试用例和里程碑）。
