# ADR-NNN：决策标题

## 状态

`拟议 | 已接受 | 已取代 | 已废弃`

## 日期

`YYYY-MM-DD`

## 背景

说明需要解决的问题、当前约束、已知风险和必须保持的产品或架构不变量。引用相关需求、契约、指标和历史决策，不记录未经验证的猜测。

## 决策驱动因素

- 必须满足的安全、数据隔离与权限条件。
- 可靠性、性能、成本和运维要求。
- 当前团队、运行环境和交付阶段约束。
- 与现有模块接口、数据写入权和未来演进的关系。

## 备选方案

### 方案 A：名称

说明接口、主要实现、收益、代价和失败模式。

### 方案 B：名称

说明接口、主要实现、收益、代价和失败模式。

## 决策

明确采用的方案、适用范围、暂不覆盖的场景和生效节点。说明该方案如何隐藏复杂性，以及调用方必须了解的最小接口。

## 影响

### 正面影响

- 说明可验证的收益。

### 负面影响与风险

- 说明新增成本、限制和残余风险。

## 验证指标

- 需要通过的功能、契约、安全、恢复或性能测试。
- 需要采集的指标及阈值。
- 不能执行的验收必须标记为 `not_run` 或 `not_configured`。

## 迁移与回滚

说明数据、接口、配置、流量和发布的迁移顺序；列出回滚触发条件、回滚步骤及不可逆操作。

## 后续事项

- 责任角色、目标阶段或日期、退出条件。

## 关联内容

- 相关架构章节、契约、实施计划、验证报告和取代/被取代 ADR。
