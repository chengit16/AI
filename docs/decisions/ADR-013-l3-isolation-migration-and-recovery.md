# ADR-013：L3 隔离迁移与恢复协议

## 状态

`已接受`

## 日期

`2026-08-17`

## 背景

ADR-012 已建立 L1～L4 隔离控制面，并在 P5-08 前由应用与数据库共同拒绝 L3 路由激活。L3 面向高合规企业，要求工作空间拥有独立数据库、对象存储桶和加密密钥，同时完成事实复制、派生索引重建、备份恢复、删除传播、原子切换和失败回滚。

数据库、MinIO 和密钥系统不共享分布式事务。若在业务事务内执行长时间复制，会长时间持有锁并把外部失败混入控制面事务；若让调用方提交资源地址、凭证或验证结论，又会绕过服务端路由和安全边界。迁移还必须避免长期双写，任何失败状态都只能保留一个权威写入位置。

## 决策驱动因素

- 浏览器、模型输出和普通业务模块不能提交数据库地址、Bucket、密钥材料、路由键或通过结论。
- 物理复制、索引重建和备份恢复可能耗时，不能在控制面数据库事务内执行。
- L3 切换前源端必须保持唯一写入权，切换后目标端才成为权威位置，不建立长期双写。
- 数据库、对象和派生索引必须分别校验，备份必须恢复到第三份干净资源后比较，不能用目标自读冒充恢复。
- 失败与恢复尝试必须只追加并可审计，跨工作空间请求不能先触发外部清理再被数据库拒绝。
- 本地 PostgreSQL、MinIO 和合成文件密钥只能证明机制，不能替代真实客户环境或生产 KMS/Vault 认证。

## 备选方案

### 方案 A：在一个长事务中复制并切换

控制面先锁定工作空间，在同一事务内复制数据库与对象，最后更新路由。该方案表面上接近原子，但 PostgreSQL 无法原子提交 MinIO、索引和密钥系统；长事务还会放大锁、连接和失败恢复风险。

### 方案 B：长期双写后逐步切流

源端和目标端同时接收业务写入，通过对账逐步提高目标流量。该方案需要跨数据库幂等、冲突解决和无限期修复机制，违背设计文档的单一写入责任和禁止长期双写要求。

### 方案 C：事务外物理迁移、不可变验证证据与原子路由提交

控制面先提交 `executing`，受信执行器在事务外复制并验证资源；控制面随后冻结资源档案和六类检查点。只有检查点全部通过且摘要一致时，数据库才允许 L3 路由与计划 `completed` 在同一事务提交。失败进入 `rollback_required`，目标清理成功后转为 `rolled_back`。

## 决策

采用方案 C，具体边界如下：

- `L3IsolationMigrationService` 只接收可信 `RequestContext` 和迁移计划 ID。数据库、对象、密钥与搜索路由键由服务端按工作空间生成，调用方和执行器都不能覆盖。
- `L3MigrationExecutor` 是窄受信端口，只在数据库事务外执行可重放的物理动作。连接 URL、MinIO 凭证和密钥路径只驻留执行进程，不进入资源档案、检查点、审计或事件。
- 资源档案只保存独立数据库、独立 Bucket、独立密钥的无凭证路由键、资源身份摘要、密钥指纹和配置摘要。源密钥与目标密钥指纹必须不同，明文密钥和密钥封装材料不持久化。
- 检查点固定为 `source_snapshot`、`database_copy`、`object_copy`、`derived_index_rebuild`、`backup_restore` 和 `deletion_propagation`。六项都必须为 `passed` 且源/目标摘要一致，失败事实同样只追加。
- 派生索引根据目标事实重新生成，不直接把旧索引作为权威事实复制。备份恢复写入第三个独立数据库和 Bucket 后再比较事实、索引和对象摘要。
- 路由切换前 `source_is_authoritative=true`、`target_writes_enabled=false`。数据库 Trigger 重新核对迁移状态、资源档案、六项检查点和路由键后，路由与 `completed` 原子提交；读取只暴露完成计划的最新路由。
- 外部执行异常、结构非法证据、任一检查点失败或控制面提交冲突进入 `rollback_required`。恢复调用在外部清理前先验证工作空间归属；每次恢复尝试只追加，只有源端权威且目标禁写时才进入 `rolled_back`。
- `PostgresMinioL3MigrationExecutor` 对工作空间事实使用显式表清单和有界快照，对对象使用工作空间前缀；目标与恢复资源不得和源资源复用。它是 S3-compatible 与 PostgreSQL 适配基线，不把本地凭证或文件密钥固化为生产接口。

## 影响

### 正面影响

- 控制面数据库事务保持短小，外部系统失败不会制造假原子提交。
- 应用和数据库双重拒绝缺证据、错路由、跨空间和提前切换。
- 迁移、备份恢复、失败回滚和删除传播都有低敏不可变证据，可由阶段验收和运营控制台复用。
- 未来接入生产 PostgreSQL、S3-compatible 存储和 KMS/Vault 时，只需替换资源解析和执行 Adapter，不改变迁移状态机与路由契约。

### 负面影响与风险

- 外部复制与控制面提交之间仍存在时间窗口，因此执行器必须可重放，控制面冲突必须进入恢复态。
- 当前有界执行器以显式表清单表达外键顺序，超出本地上限的大型工作空间需要后续流式、分批和断点实现，不能直接提高上限冒充容量认证。
- 本地合成文件密钥只能验证独立指纹和不落库边界，不能证明生产密钥轮换、HSM、权限或审计集成。

## 验证指标

- 合成高合规工作空间在真实临时 PostgreSQL 数据库与三个独立 MinIO Bucket 间完成复制和第三资源恢复。
- 其他工作空间的数据库行和对象不进入目标资源，删除墓碑引用的对象在源端和目标端均保持不存在。
- 派生索引由目标事实重建，源/目标摘要一致；独立密钥指纹不同且资源档案不含凭证或密钥材料。
- 缺少档案、检查点失败、错误路由键、跨空间激活或恢复、档案/检查点改写删除均失败关闭。
- 切换前解析仍为 L1/L2 源路由，切换提交后才解析 L3；失败清理完成后计划进入 `rolled_back` 且可以创建新计划。

## 迁移与回滚

Revision `20260817_0067` 只新增 L3 资源档案、迁移检查点和恢复记录，并替换 L3 路由插入 Trigger；L1、L2 和未执行 L3 计划的运行行为不变。升级后 L4 仍由数据库拒绝，等待 P5-10。

降级前必须确认三张 P5-08 表为空；存在资源档案、检查点或恢复事实时不得破坏性删除历史。迁移失败使用同一计划的 `rollback_required → rolled_back` 收口，不能删除计划或档案来伪造未执行。已完成 L3 路由的反向迁移必须创建新的已批准迁移方案并保持单一写入权，不能直接修改或删除既有路由。
