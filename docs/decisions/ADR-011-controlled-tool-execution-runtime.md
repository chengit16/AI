# ADR-011：受控工具执行 Runtime 与副作用提交协议

## 状态

已接受

## 日期

2026-08-16

## 背景

阶段 3 已交付不可变 `AgentRelease`、统一服务调用出口和 Runtime 发布装载隔离，但发布快照中的工具引用仍只允许只读配置，尚不存在统一的工具注册、任务状态、确认、幂等、副作用执行、取消和结果安全协议。若模型、页面、Worker 或各业务模块直接调用工具，不同入口会分别解释权限、确认和重试，至少一次投递也可能造成重复外部副作用。

阶段 4 首批只正式开放五个内部只读工具。写操作只使用全合成内部 Adapter 验证控制机制，不接入任意 HTTP、SQL、文件系统、真实企业系统、付款、发送或删除类真实能力。设计仍需提前冻结写操作的安全协议，否则后续接入真实工具时会被迫改变状态事实和审计语义。

## 决策驱动因素

- 模型输出与客户端请求均不可信，不能决定最终工具版本、权限、凭证或调用时机。
- Release 允许列表是发布上限，当前权益、成员状态和 RBAC/ABAC 是执行时上限，任一收窄都必须立即生效。
- 写入和高风险操作必须由可验证的个人确认或企业审批授权，且授权不能在参数或策略变化后复用。
- 队列至少一次投递、Worker 重启、超时和响应丢失不能造成重复副作用。
- 取消、超时与迟到结果必须有确定性优先级，历史 Attempt 不能被覆盖。
- 工具凭证和结果都跨越不可信边界，必须在最窄调用边缘注入和清洗。
- 当前保持 Python 模块化单体，不引入 Durable Run、Go 运行层或真实连接器。

## 备选方案

### 方案 A：模型或业务模块直接调用工具

每个工具自行校验参数、权限和凭证，初期代码量较少，但模型可以影响调用边界，多个入口会形成不同确认、重试和审计语义，也无法集中证明凭证零泄漏与重复副作用为零，因此拒绝。

### 方案 B：复用普通异步任务，只在高风险工具前弹窗

继续使用既有 Worker Lane 和任务 Attempt，在页面层增加确认。该方案可以复用部分可靠性底座，但页面确认无法保护 API 或模型旁路，普通任务也没有工具版本、规范参数摘要、幂等副作用和迟到结果优先级等事实，因此拒绝。

### 方案 C：建立窄工具执行 Runtime，复用平台横切能力

建立统一工具执行应用边界，拥有 Run、Step、Attempt、ToolCall 和幂等提交协议；复用 AgentRelease、策略中心、审批、凭证、Worker、Outbox、SSE、审计和用量，不复制这些事实源。模型只提交候选意图，确定性 Runtime 完成其余决策。采用此方案。

## 决策

- 阶段 4 建立独立 `tool_execution` 模块，作为工具任务与副作用幂等事实的唯一写入方。业务资源仍由原领域模块拥有，工具 Adapter 只能调用公开应用端口，不能跨模块直接写表。
- 每个 Run 固定 `AgentRelease`、可信调用主体、工作空间和预算；每个 Step 固定工具 ID、工具版本、规范参数摘要与顺序。模型输出只能成为候选 ToolCall，不能直接进入 Adapter。
- 执行前按顺序完成 Release 允许列表、不可变工具版本、参数 Schema、工作空间权益、当前 RBAC/ABAC、风险策略、确认/审批和预算检查。任一步失败均不创建 Adapter 调用。
- 只读调用可以在策略通过后执行；任何副作用调用必须绑定有效确认事实。个人空间由所有者确认，企业空间复用既有审批引擎。确认摘要包含 Run、Step、工具版本、规范参数摘要和策略版本；参数、工具版本或策略变化使旧确认失效。
- 副作用发生前先持久化稳定幂等身份与请求摘要。相同键和相同摘要只返回既有结果，相同键和不同摘要返回 `IDEMPOTENCY_CONFLICT`。无法证明既有调用结果时进入人工恢复，不自动再次触发副作用。
- Attempt 采用租约和追加式历史。取消、超时或租约失效后禁止创建新 Attempt；已发出的底层调用尽力取消。迟到响应可以写入独立审计证据，但不能把 `cancelled`、`timed_out` 或其他终态改回成功。
- 凭证只以 `credential_ref` 持久化，在 Adapter 调用边缘按当前授权解密并短时注入。工具参数、结果、日志、事件、SSE、审计、Trace 与错误对象均不得包含明文凭证。
- Adapter 结果先执行 Schema、大小、敏感字段和 Prompt Injection 检查。未通过检查的结果不能进入后续模型上下文，并以稳定错误和最小化审计关闭当前调用。
- 首批正式工具固定为 `knowledge.search`、`document.read_authorized_range`、`workflow.get_status`、`approval.get_status` 和 `quota.get_usage`。合成写 Adapter 只用于阶段 4 测试，不进入真实客户或供应商边界。

## 影响

### 正面影响

- 页面、API、模型和 Worker 共享同一权限、确认、幂等、取消和审计语义。
- 副作用调用具有可复算身份，重复投递、响应丢失和 Worker 重启能够验证零重复写入。
- Release 允许列表与当前策略共同收窄权限，撤权无需重发 Release 即可失败关闭。
- 凭证注入和结果清洗集中在最窄边界，减少敏感信息进入模型与观测系统的机会。

### 负面影响与风险

- 新增 Run、Step、Attempt、ToolCall、确认绑定和幂等事实，Migration、事务和恢复测试数量明显增加。
- 副作用结果无法确定时必须人工恢复，不能为了可用性自动重试；这会牺牲部分自动恢复速度。
- 当前阶段只用合成写 Adapter，不能替代真实外部系统的幂等能力、限流、数据政策和可用性验收。
- 取消只能阻止后续工作并尽力传播，已经被外部系统提交的副作用不能被本地终态自动撤销。

## 验证指标

- 草稿工具、未登记版本、Release 未允许工具、跨空间工具和已撤权调用全部零 Adapter 调用失败关闭。
- 未确认、确认过期、参数变化和企业审批未完成的副作用调用均为零；个人和企业确认路径可重复验证。
- 相同幂等键同摘要重复投递只产生一次副作用，同键异摘要稳定拒绝；响应丢失后不盲目重放。
- 取消、超时和 Worker 租约失效后不创建新 Attempt；迟到成功不能覆盖已提交终态。
- Prompt、模型上下文、数据库非密文字段、事件、日志、审计正文、SSE、异常和测试证据中的明文凭证数量为零。
- 工具结果安全检查失败时不进入后续模型上下文，失败样本仍进入低基数运营统计。
- 专项契约、安全、真实 PostgreSQL、故障注入、统一门禁和容器诊断按各节点计划通过；真实外部系统与容量结论保持 `not_run`。

## 迁移与回滚

- `P4-01` 只新增契约和 ADR，没有数据库与运行时迁移，可直接移除未被实现引用的新增契约回滚。
- `P4-02` 起按工具注册、任务事实、只读 Adapter、确认、凭证和副作用协议的顺序逐步建表与启用能力；每次 Revision 都必须提供空库、非空库和降级测试。
- 写 Adapter 默认保持禁用。任何节点验收失败时停止激活新菜单和 API，保留既有阶段 3 服务调用路径，不允许降级为模型直调或页面确认。
- 一旦产生副作用幂等事实，数据库降级不得静默删除；必须先停止新调用、导出最小恢复清单并证明没有未决结果。

## 后续事项

- `P4-02` 实现不可变工具版本与工作空间可用目录。
- `P4-03` 实现 Run、Step、Attempt、ToolCall、租约和数据库状态约束。
- `P4-04` 接入五个冻结内部只读工具，并复用资源模块的 RBAC/ABAC 与字段过滤。
- `P4-06`～`P4-09` 依次实现确认/审批、凭证注入、合成副作用和取消恢复协议。
- 真实外部工具、真实连接器和长任务在阶段 4 结束后按独立指标重新立项。
