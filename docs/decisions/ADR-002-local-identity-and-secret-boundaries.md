# ADR-002：本地身份认证与凭证存储边界

## 状态

`已接受`

## 日期

2026-08-13

## 背景

阶段 1 需要同时支持浏览器用户和 Open API Key 调用方，并保证客户端不能通过伪造账号、工作空间或权限范围构造可信 `RequestContext`。当前平台先以本地 Docker 方式运行，不依赖 SaaS 身份服务；PostgreSQL 是账号、成员关系和凭证元数据的事实来源，Valkey 只能保存可失效、可重建的短期会话状态。

平台后续还需保存模型供应商 Key。Open API Key 只用于验证调用方，不需要恢复明文；供应商 Key 则必须在调用供应商时恢复。两类秘密若共用同一种存储方式，会扩大明文恢复能力和主密钥泄漏后的影响范围。

## 决策驱动因素

- 所有可信身份、工作空间和凭证 Scope 必须由服务端根据已验证凭证重建。
- 浏览器会话撤销、账号停用、密码变更和成员关系变更必须及时生效。
- Open API Key 明文只允许在签发时返回一次，数据库和日志不得保存可恢复值。
- 模型供应商 Key 需要可逆加密，并支持后续主密钥轮换和逐条数据密钥重包裹。
- 本地启动必须能安全生成密钥，同时保持容器只读挂载和仓库零秘密材料。

## 备选方案

### 方案 A：无状态 JWT 同时承载身份、空间和权限

调用链读取成本较低，但成员停用、撤权和账号状态变化无法立即生效，必须引入吊销列表或缩短有效期。把工作空间和权限声明长期固化在客户端令牌中，也会增加伪造、陈旧声明和跨空间误用风险。

### 方案 B：服务端 Session、逐请求事实校验和分类型秘密存储

浏览器只持有随机 Session Token，Valkey 以 Token 摘要作为键；服务端逐请求检查 PostgreSQL 中的账号、认证版本、空间和成员状态。Open API Key 只保存单向摘要，可逆供应商 Key 使用 AES-256-GCM 信封加密。该方案增加一次事实读取，但撤权及时且秘密职责清晰。

### 方案 C：所有凭证统一使用可逆数据库加密

实现形式一致，但 Open API Key 无需恢复明文。为其保留解密能力会扩大主密钥泄漏后的风险，且不符合最小能力原则。

## 决策

采用方案 B，并固定以下边界：

1. 账号密码使用 Argon2id 独立盐哈希；登录失败统一返回稳定错误，不暴露账号是否存在。
2. 浏览器 Session 使用高熵随机 Token，Valkey 键只保存 Token 的 SHA-256 摘要；会话载荷只包含账号 ID、认证版本和 CSRF 摘要，默认有效期 12 小时。
3. 浏览器写请求执行与 Session 绑定的 CSRF 校验；Cookie 使用 `HttpOnly`、`SameSite=Strict`，非本地环境强制 `Secure`。
4. 每次受保护请求都从 PostgreSQL 复核账号、工作空间和成员状态；账号认证版本变化立即吊销旧 Session。客户端提供的 `X-Workspace-ID` 只作为目标标识，不作为授权事实。
5. Open API Key 使用独立 `actor_id` 和最小 Scope，明文只在签发响应中出现一次；数据库仅保存 SHA-256 摘要、末四位、有效期和撤销状态。Open API Key 不经过可逆加密。
6. 需要恢复明文的供应商 Key 使用每条秘密独立数据密钥的 AES-256-GCM 信封加密。32 字节平台主密钥由本地启动器生成，权限固定为 `0600`，以只读文件挂载给 API；仓库、数据库和日志均不保存主密钥。
7. HTTP 边缘只接受浏览器 Session 或 `Authorization: Bearer` Open API Key，并生成可信 `RequestContext`。业务模块不得直接信任客户端传入的账号、Actor、Scope 或成员关系。

本节点只建立认证、会话、上下文和凭证安全底座。注册、默认个人空间、企业成员生命周期、角色与 ABAC 分别由 `P1B` 和 `P1C` 实现。

## 影响

### 正面影响

- 账号或成员状态改变后，无需等待长令牌过期即可阻止后续访问。
- Open API Key 不具备数据库解密路径，供应商 Key 的可逆能力被限制在专用 Adapter。
- `RequestContext` 对浏览器和 API Key 调用方保持统一，后续策略模块无需解析凭证协议。
- 主密钥版本和逐条数据密钥为后续轮换预留稳定边界。

### 负面影响与风险

- 每个受保护请求至少需要一次 Session 读取和账号、成员事实查询，后续需通过测量决定是否引入短期授权缓存。
- Valkey 不可用时浏览器 Session 默认失效，当前不提供离线认证降级。
- 本地主密钥丢失会导致可逆供应商凭证无法恢复，因此备份与恢复必须把密钥文件作为独立敏感资产处理。
- SHA-256 只适用于本方案生成的高熵随机 Session/API Key，不得用于用户密码或低熵秘密。

## 验证指标

- 伪造 Session、无效 Bearer、跨空间 ID、停用成员、停用账号和过期或撤销 Key 均失败关闭。
- CSRF 缺失或不匹配时，浏览器写请求被拒绝；安全读取请求不要求 CSRF。
- Session Token 和 Open API Key 明文不进入 Valkey 键、PostgreSQL 行、错误响应或日志。
- 密码哈希可验证且不同盐产生不同结果；错误账号与错误密码使用同一公开错误。
- 信封加密密文不能在关联数据变化时解密，错误权限、符号链接或错误长度的主密钥被拒绝。
- Migration 能从空库升级到 `20260813_0004`，完整降级后再升级得到一致结构。

## 迁移与回滚

1. `P1A-04` 新增账号、工作空间成员和 Open API Key 表，不迁移真实账号或凭证。
2. 本地启动时在 `.ai-platform/secrets/master.key` 生成主密钥；已有正确密钥保持不变。
3. API 容器只读挂载主密钥。身份模块未启用可逆供应商凭证时延迟读取，避免普通登录被无关配置阻塞。
4. 若节点验收失败，可将 Migration 降级到 `20260813_0003` 并移除身份 Router；当前仅有合成数据，无不可逆业务迁移。
5. 一旦保存真实供应商凭证，回滚或轮换前必须先导出加密记录并验证原主密钥备份，不得直接重新生成密钥。

## 后续事项

- `P1B-01` 建立注册、默认个人空间和所有者事实，并复用本 ADR 的密码与 Session 边界。
- `P1C` 将 Open API Key Scope 接入统一权限码和策略决策点；Scope 只限制凭证能力，不能扩大创建者权限。
- `P1D-05` 持久化供应商密钥时补充密文字段、关联数据格式和主密钥轮换演练。
- `P1G-03` 将主密钥备份、恢复和轮换纳入本地恢复演练。
