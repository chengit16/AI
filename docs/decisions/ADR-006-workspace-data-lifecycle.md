# ADR-006：工作空间数据生命周期与可校验导出包

## 状态

已接受

## 日期

2026-08-15

## 背景

阶段 1 已提供覆盖 PostgreSQL、MinIO 和文件型密钥的整实例 `.aiprb` 恢复包，但它面向本地实例灾难恢复，包含多个工作空间及平台级配置，不能作为单个工作空间的数据导出。阶段 2 还需要在不破坏个人账号登录和企业治理入口的前提下，清除一个工作空间的业务数据，并证明数据库事实、对象、派生索引和缓存均已处理。

个人账号必须始终拥有唯一活动个人空间。若把“删除个人空间”实现为物理删除 `workspaces` 及所有成员关系，账号将无法完成后续登录；企业空间同样需要保留可审计的所有权和治理入口。因此，普通生命周期删除不能等同于删除工作空间实体。

## 决策驱动因素

- 导出结果只能包含目标工作空间，不得混入其他工作空间、平台密钥或供应商凭据。
- 导出文件必须可重复校验表级行数、对象大小和 SHA-256，不能只返回一个不可验证的下载地址。
- 删除必须覆盖业务事实、对象、派生索引、缓存和可删除事件，同时保留有明确依据的最小治理事实。
- PostgreSQL、MinIO 和 Valkey 无法跨介质原子提交，流程必须允许安全重试并提供最终证明。
- 不可变触发器仍是普通业务事务的安全边界，生命周期清理不能永久降低其保护强度。

## 备选方案

### 方案 A：复用整实例 `.aiprb` 恢复包

实现成本最低，但会混入其他工作空间和平台级秘密，无法满足工作空间隔离，也不能证明单个空间的导出完整性，因此拒绝。

### 方案 B：物理删除工作空间及全部关联记录

数据库外键可帮助删除大量数据，但会破坏个人空间不变量，也会丢失必要的所有权、最小审计和删除证明，因此拒绝。

### 方案 C：独立工作空间导出包与保留壳层的数据清除

导出、清除和保留期执行使用显式表分类；删除只清除业务域，保留可登录、可治理、可审计的最小空间壳层，并通过幂等请求和不可变证明跨越多种存储，采用此方案。

## 决策

### 工作空间导出

- 使用独立的 `workspace-export.v1` ZIP 包，不复用 `.aiprb` 扩展名或恢复语义。
- 包内包含规范化 `manifest.json` 和按表排序的 JSONL 文件；时间、UUID、二进制和 JSON 值使用稳定序列化。
- Manifest 记录工作空间 ID、格式版本、注册表版本、每个表的行数、文件大小和 SHA-256，以及每个 MinIO 对象的对象键、大小和 SHA-256。
- 导出包排除密码 Hash、API Key 摘要、模型供应商凭据、平台主密钥和 Session；工作空间 API Key 只导出不含 `secret_digest` 的治理元数据，不能由导出包恢复原 Key。
- 导出对象保存到 `workspaces/{workspace_id}/exports/{export_id}.zip`，完成记录保存包大小、摘要和对象清单摘要。

### 数据分类

每张含 `workspace_id` 的表必须在代码注册表中被明确归入以下一类；数据库集成测试发现未分类新表时直接失败：

- `business`：知识、入库、索引、检索、助手、模型调用、工作流、审批、流式事件等可清除业务事实。
- `governance`：工作空间、Owner、成员、组织、角色、权限、菜单、套餐和功能设置，作为空间壳层保留。
- `retained`：最小审计、用量账本和已完成删除证明，按冻结保留期保存。
- `lifecycle`：导出、删除请求和保留期执行记录，由生命周期流程按自身状态处理。

### 删除语义

- 对个人版和企业版统一提供“清除工作空间业务数据”，不在本节点提供物理删除工作空间实体。
- 只有具有独立生命周期删除权限的浏览器 Owner 可以发起；请求必须包含工作空间名称确认、结构化原因和幂等键，API Key 不得触发。
- 数据库先删除 `business` 类事实及旧的可删除 Outbox，业务入口立即无法再读取原内容；随后幂等删除 `workspaces/{workspace_id}/` 下的业务对象与导出对象，并删除包含工作空间 ID 的 Valkey 派生键。
- 全部介质完成后，追加最小审计、完成事件和不可变删除证明。证明只保存分类版本、各表删除行数、对象数、缓存键数、摘要和时间，不保存原业务正文。
- 外部存储失败时，请求保持 `retryable`，同一幂等键再次提交继续未完成步骤；幂等键绑定到另一请求内容时拒绝。

### 不可变事实与保留期

- 生命周期事务通过事务级 `ai_platform.lifecycle_purge=on` 请求受限旁路；只有生命周期 Repository 会设置该值。
- 审计、Attempt、工作流版本、审批动作、助手和检索快照的触发器仅在该事务值为 `on` 时允许删除，普通事务行为保持不变。
- SSE 事件保留 24 小时；已投递 Outbox 保留 30 天；Job Attempt 和 Outbox Dead Letter 保留 90 天；最小审计、用量与删除证明保留 365 天。
- 保留期执行产生只含截止时间、删除计数和摘要的记录，不把已删除正文复制到证明中。

## 影响

### 正面影响

- 工作空间导出与整实例恢复职责清晰，避免跨空间和凭据泄漏。
- 个人空间在清除业务数据后仍可登录和继续使用，企业空间仍可治理成员与权限。
- 新增表必须显式声明生命周期策略，后续功能不会静默漏出导出或删除范围。
- 跨存储失败可重试，最终结果可由摘要和删除证明独立核对。

### 负面影响与残余风险

- 导出包当前只承诺可读和可校验，不承诺工作空间级自动导入；导入需要单独解决 ID 冲突、权限映射和版本迁移。
- 清除期间数据库与对象存储存在短暂不一致窗口，但数据库先撤销业务可见性，孤立对象不能由应用读取。
- 本地 MinIO 与 Valkey 验收不能替代未来云对象存储、分布式缓存和法务保留要求的生产认证。

## 验证指标

- 目标空间导出包的全部表与对象摘要复算一致，且不包含第二工作空间或凭据字段。
- 表分类注册表覆盖数据库中全部含 `workspace_id` 的表，新增未分类表使测试失败。
- 重复导出和删除请求按幂等键返回同一事实；不同请求内容复用幂等键被拒绝。
- 删除后业务类表、工作空间对象前缀和派生缓存均为空，空间壳层、最小审计、用量和删除证明仍存在。
- 普通事务仍不能删除不可变事实，只有事务级生命周期旁路可执行受控清理。
- 保留期边界前一秒的数据保留，达到截止时间的数据被删除并计入执行记录。

## 迁移与回滚

- Revision `20260815_0040` 新增生命周期事实、权限和受限触发器旁路。
- 升级不自动导出或清除现有空间；只有显式授权请求才执行。
- 回滚 Revision 前必须确认不存在运行中的生命周期请求；回滚删除新增事实并恢复原不可变触发器定义，不恢复已经按授权请求清除的业务数据。

## 后续事项

- 阶段 2 运营工作台提供导出、删除、保留期运行状态和危险操作确认界面。
- 工作空间级导入能力在明确冲突策略与迁移兼容矩阵后单独立项。
- SaaS 部署前补充区域性法定保留、Legal Hold、对象版本与云存储删除标记策略。
