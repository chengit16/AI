# ADR-001：阶段 1A 使用 Valkey 替换 Redis 7.4

## 状态

`已接受`

## 日期

2026-08-13

## 背景

阶段 0 本地编排固定使用 Redis 7.4，承担队列、唤醒、锁和缓存等非事实状态。Redis 7.4 采用 RSALv2 或 SSPLv1，虽然可用于当前本地技术验证，但其许可证边界不适合作为项目默认商业发布依赖。平台尚未进入阶段 1 业务开发，当前是替换基础设施且避免形成迁移债务的最低成本窗口。

平台必须继续保持以下不变量：PostgreSQL 保存业务与事件事实；缓存不可成为唯一数据源；应用通过 Adapter 使用缓存能力；本次替换不得扩展为 SaaS、多活或 Go 运行层建设。

## 决策驱动因素

- 默认本地与后续商业发布组合需要清晰、可复核的开源许可证边界。
- 现有 Redis 使用范围应兼容迁移，避免改写阶段 0 已验证的业务事实模型。
- 本地 Docker 一键运行、健康检查、Worker 和 SSE 唤醒能力必须保持。
- 组件版本、镜像摘要和许可证需要进入阶段 1A 的 `ReleaseManifest`。

## 备选方案

### 方案 A：继续使用 Redis 7.4

技术改动最小，但需要长期隔离商业发布组合并承担许可证复核成本，容易让本地默认配置与可发布配置分叉。

### 方案 B：阶段 1A 替换为 Valkey 8.x

Valkey 使用 BSD-3-Clause，并保持 Redis 协议兼容。需要重新执行容器、客户端、恢复和并发测试，但在业务模块大量依赖缓存前完成替换，整体迁移成本可控。

### 方案 C：立即引入其他队列或缓存产品

可能获得不同的运维特性，但会扩大阶段 1A 范围并迫使应用同时调整协议和客户端，不符合当前本地 MVP 的最小变更原则。

## 决策

采用方案 B。阶段 0 保留 Redis 7.4 的历史验证结论，不修改已完成节点；`P1A-02` 将默认镜像替换为 Valkey `8.1.5-alpine@sha256:918228e4ff7da6b3a4213cb18067f6e09d9f0503d0a08868699ba227cff71861`，该清单包含 `linux/amd64` 和 `linux/arm64`。应用侧继续通过缓存与唤醒 Adapter 使用 RESP 能力，不把供应商名暴露到领域接口。

替换节点只处理当前已使用能力，不同时引入集群、哨兵、托管服务或新的消息中间件。替换通过后，Redis 7.4 从默认本地运行组合和未来商业发布清单中移除。

## 影响

### 正面影响

- 默认基础设施采用宽松许可证，降低后续分发和商业化的不确定性。
- RESP 兼容使应用代码和数据职责边界基本不变。
- 在阶段 1 开始时完成替换，可避免业务模块对 Redis 品牌或私有能力形成耦合。

### 负面影响与风险

- 需要重新拉取镜像并验证 ARM64、macOS 和 Linux Docker 运行。
- 必须验证持久化目录、健康检查、客户端命令、队列和 SSE 唤醒兼容性。
- 未来若使用 Redis 专有命令或模块，不能假定 Valkey 必然兼容，必须另行 ADR。

## 验证指标

- `docker compose config --quiet` 和 `./platform doctor` 通过。
- API、Worker、缓存、锁、队列和 SSE 唤醒相关测试全部通过。
- 停止并重新启动后，允许持久化的非事实缓存数据可按设计恢复或重建。
- 默认运行组合不再引用 Redis 7.4，SBOM、许可证清单和 `ReleaseManifest` 固定 Valkey 版本与镜像摘要。
- 现有工作空间、Outbox 和 SSE PostgreSQL 事实测试无回归。

## 迁移与回滚

1. 在阶段 1A 独立节点中固定 Valkey 8.x 镜像和健康检查。
2. 使用全新的合成缓存数据启动，执行协议、恢复和故障测试；不迁移真实业务数据。
3. 更新本地编排、配置名、文档和供应链产物，应用 Adapter 接口保持不变。
4. 若发现当前使用命令不兼容，节点验收失败并回滚编排文件；Redis 7.4 仅可继续用于本地验证，不能进入商业发布包。

本次替换没有不可逆业务数据操作，因为 PostgreSQL 仍是唯一事实来源，缓存与队列状态必须可重建。

## 后续事项

- 阶段 1A 将 Valkey 版本、镜像摘要和许可证写入 `ReleaseManifest`。
- 采用 Redis/Valkey 非通用模块或托管服务前重新评审兼容性与许可证。

## 实施结果

`P1A-02` 已完成替换：默认 Compose 不再包含 Redis 服务，Valkey 使用独立 `data/valkey` 目录，旧 `data/redis` 目录保留但不挂载。实际容器报告 `server_name=valkey`、`valkey_version=8.1.5`；合成旧缓存标记未被导入，新 Valkey 合成标记在容器重启后可由 AOF 恢复。API、Worker、SSE PostgreSQL 基线和七项平台诊断均通过。
