# ADR-012：版本化工作空间隔离控制面

## 状态

`已接受`

## 日期

`2026-08-17`

## 背景

设计文档第 15 节将工作空间隔离分为 L1 逻辑隔离、L2 命名空间隔离、L3 数据库隔离和 L4 部署隔离，并要求平台根据套餐与合规要求决定等级。阶段 5 需要先建立可验证的资格、迁移计划和路由约束，再由 P5-08、P5-10 分别实施 L3、L4 物理资源迁移。

现有 Identity 模块拥有 `workspace_entitlements` 写入权，Lifecycle 模块拥有导出与清除流程，各业务模块通过可信 `RequestContext` 和 `workspace_id` 强制隔离。P5-07 不能把隔离等级变成客户端参数，也不能让业务模块直接读取数据库地址、对象存储凭证或密钥材料。

## 决策驱动因素

- 客户端、模型输出和普通业务模块不能覆盖隔离等级或数据平面路由。
- 套餐、工作空间类型、合规审核、迁移状态和路由必须形成可追溯的一致事实。
- L3/L4 尚无真实客户环境、生产 KMS/Vault 或独立部署目标，未知外部条件必须保持 `not_configured`。
- 迁移不得长期双写；切换失败时必须保留单一权威写入位置和回滚计划。
- Identity、Lifecycle 与 Isolation 的数据写入权必须清晰，避免跨模块修改私有表。

## 备选方案

### 方案 A：在 `workspaces` 增加可变等级和路由列

由 Identity 模块同时保存当前等级、数据库地址、对象桶和密钥引用。实现直接，但会把套餐、合规、迁移和运行路由耦合到账号聚合；普通空间更新容易误改隔离状态，也无法保留完整决策与切换历史。

### 方案 B：独立的版本化隔离控制面

Isolation 模块只读取工作空间和套餐事实，自主管理不可变策略版本、受约束迁移计划和不可变路由版本。业务调用方只按工作空间解析当前路由，目标等级、合规结论和路由键均不能作为运行时覆盖参数。

### 方案 C：立即为全部企业空间建立独立数据库

直接把企业空间迁移到 L3。该方案在没有客户资格、目标容量、KMS、对象存储和恢复证据时扩大运维面，也违背分级隔离和先验证后切换原则。

## 决策

采用方案 B。新增 Isolation 模块，边界如下：

- Identity 继续独占工作空间和套餐写入；Isolation 通过最小读取端口获取 `workspace_type`、`plan_code`、套餐版本和空间状态。
- 隔离策略版本记录请求等级、当前等级、套餐上限、合规状态、决定和低基数原因码；策略事实只追加，不允许普通更新或删除。
- 升级必须先创建迁移计划，再经过独立批准和固定状态机。未批准、资格漂移、状态越级和目标资源未配置均失败关闭。
- 路由版本只保存不含凭证的服务端路由键。无路由版本时仅允许解析为固定 L1 共享路由；L2 路由由服务端按工作空间生成独立搜索命名空间。
- L3 路由必须等待 P5-08 完成独立数据库、对象桶、密钥的迁移校验；L4 路由必须等待 P5-10 完成独立实例档案。P5-07 不以占位字符串宣称这些环境已配置。
- 路由版本只有关联迁移计划达到 `switch_ready` 时才能插入，并与计划完成状态在同一事务收口。读取只选择已完成计划对应的最新版本；P5-08、P5-10 完成前，数据库也拒绝插入 L3/L4 路由。
- 等级变更采用停止旧写入、校验目标和原子切换路由的顺序，不建立长期双写。需要物理数据搬迁的观察、清理和反向迁移由 P5-08、P5-10 在资源证据完整后实现。

## 影响

### 正面影响

- 调用方只依赖按工作空间解析路由的窄接口，不接触套餐、合规和迁移细节。
- 决策、计划与路由历史可审计，错误路由和未批准升级可由应用与数据库共同拒绝。
- P5-08、P5-10 可以复用同一状态机和路由契约，不需要改变业务模块的 `workspace_id` 隔离接口。

### 负面影响与风险

- 新增控制面表和状态机，Migration、生命周期和恢复测试面扩大。
- 当前本地环境只能完整激活 L2；L3/L4 的真实资源与恢复结论继续为 `not_configured`。
- 隔离路由解析成为共享运行依赖，后续接入业务路径时必须采用默认拒绝和低基数观测，不能静默回退到 L1。

## 验证指标

- 契约固定四级隔离、套餐上限、合规状态、迁移状态和允许转换。
- 个人空间越级、未知套餐、未审核 L3/L4、套餐版本漂移、未批准切换和跨工作空间读取全部失败关闭。
- L2 切换后数据库与对象存储仍为共享路由，搜索命名空间按工作空间唯一；调用方不能覆盖解析结果。
- 策略与路由普通更新/删除由数据库拒绝，迁移计划越级或跳版本由 Trigger 拒绝。
- L3/L4 真实目标环境、容量和恢复未配置时记录为 `not_configured/not_run`。

## 迁移与回滚

Revision `20260817_0066` 只新增隔离控制面表和 Trigger，不修改现有业务表或运行路由。升级后没有策略或路由版本的工作空间仍确定性解析为 L1，因此现有行为不变。

回滚 Revision 前必须确认三张隔离表为空；存在策略、计划或路由事实时拒绝破坏性降级。路由激活前的失败通过当前计划进入 `rollback_required` 和 `rolled_back` 收口，期间不得创建第二个迁移计划。P5-07 不持久化 L1 路由，也不声称已完成激活后的反向迁移；L3/L4 物理切换及其反向迁移由 P5-08、P5-10 以新的已批准计划和单一权威写入位置实现，历史事实不得删除。

## 后续事项

- P5-08 实现 L3 目标资源档案、复制校验、备份恢复、原子切换和回滚。
- P5-09 把已配置法域和法规策略接入合规资格端口。
- P5-10 实现 L4 独立实例部署档案、升级和恢复。
- P5-12 提供带权限与危险确认的隔离治理控制台；P5-07 不提前开放浏览器写接口。
