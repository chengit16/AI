# ADR-016：固定知识组织与企业治理对象边界

## 状态

`已接受`

## 日期

`2026-08-21`

## 背景

现有知识模块已经以 `KnowledgeBase → Document → DocumentVersion → DocumentPublication` 保存知识内容、版本和当前发布事实。第一版产品化改造需要增加文件夹、标签、收藏、回收站、企业分类和团队知识域。如果把这些页面概念分别实现为文档容器，或者通过前端双写隐式复制文档与 Chunk，会形成多个内容事实源、破坏当前发布与检索链路，并放大参考站已经出现的入口不同步和跨空间泄露风险。

第一版同时明确不建设在线正文、富文本编辑、自动保存和多人实时协作。企业审批只应决定哪个不可变文档版本可以成为当前发布版本，不能让上传、解析和索引任务依赖人工审批后才保存事实。

## 决策驱动因素

- 继续复用已经验收的文档版本、发布指针、解析、索引、检索、权限和审计事实。
- 所有读取和写入必须以可信 `RequestContext.workspace_id` 为边界，并在服务端执行资源级授权。
- 文件夹、企业分类和团队知识域需要表达不同的组织、治理和检索语义，不能因页面相似而合并。
- 存量数据迁移必须兼容新增、可重跑、可核对，且不能改变既有文档可见范围和检索结果。
- 后续在线编辑器如立项，需要独立评审正文版本、冲突、恢复和索引一致性，不应预建空模型。

## 备选方案

### 方案 A：每个页面容器都拥有一份文档和索引

文件夹、知识库、企业分类和团队空间各自保存或复制文档。页面查询直接读取自己的容器，初期实现直观，但需要双写或复制版本、发布、权限和 Chunk，无法保证删除、撤权、审批和索引切换的一致性。

### 方案 B：保留唯一内容事实，新增显式组织关系

知识模块继续拥有文档、版本、来源、发布和索引；文件夹只组织文档，企业分类只表达治理分类，团队知识域只表达企业协作与 RAG 边界。跨对象关系使用带 `workspace_id` 的显式关系事实，不隐式复制内容。

### 方案 C：把文件夹等同于知识库

每个文件夹自动创建一个知识库，以目录树代表检索范围。该方案减少一种表面概念，但会把目录移动变成检索域迁移，破坏现有知识库配额、权限、Agent Release 知识范围和索引语义。

## 决策

采用方案 B，并固定以下边界：

1. `KnowledgeBase` 是可检索边界和现有权限/配额资源；`KnowledgeFolder` 是同一工作空间内的内容组织节点，二者不得互相隐式创建。
2. 一个活动 `Document` 在第一版恰好归属一个活动文件夹；同一 `KnowledgeBase` 可以关联多个文件夹，文件夹移动不复制文档版本、来源、对象或 Chunk。
3. `KnowledgeTag` 是工作空间级标签，使用显式多对多关系绑定文档；标签既不授予权限，也不扩大检索范围。
4. `DocumentFavorite` 是账号在工作空间内的私有偏好；它不改变文档所有权和其他成员视图。
5. `EnterpriseCategory` 只存在于企业工作空间，表达治理分类、可见策略和发布审批策略；文档通过关系绑定分类，不复制内容。
6. `TeamKnowledgeDomain` 只存在于企业工作空间，拥有唯一企业归属、成员/部门范围、知识库集合和 RAG 策略版本；运行时范围始终取“知识域声明范围 ∩ 当前 PDP 授权”，空交集返回空结果。
7. 企业文档审批的对象是不可变 `DocumentVersion` 的“发布请求”。通过后，知识模块在当前授权复核成功的事务中切换 `DocumentPublication`；驳回、撤回或过期不删除上传版本和解析产物。
8. 删除文档先进入回收站并立即退出普通列表和检索；恢复回到原文件夹，原文件夹不可用时回到工作空间默认根目录。永久删除只由保留期到期或有权限的显式命令触发，并沿用数据生命周期清理链。
9. 第一版不新增在线正文表、编辑 revision、自动保存契约、编辑路由或文档 AI 写回。相关能力统一进入 `POST-EDITOR-01`。

## 影响

### 正面影响

- 目录、治理分类和团队协作均复用同一文档版本、发布、索引和审计事实。
- 文件移动、分类调整和知识域绑定可以独立演进，不需要复制对象或重建未变化的 Chunk。
- 企业审批、AI 企业大脑和 Agent 知识范围可以从同一发布事实与授权交集追溯。
- 后续在线编辑器可以独立选择正文模型，不污染第一版迁移。

### 负面影响与风险

- 页面聚合查询需要跨组织关系与知识读模型组合，必须控制查询数量和分页稳定性。
- 文档当前只能有一个主文件夹；如未来需要快捷方式，应新增明确的快捷方式对象，不能把多父目录偷偷加入第一版。
- 团队知识域和知识库是多对多关系，运行时必须防止缓存或客户端参数扩大服务端交集。
- 旧客户端在兼容窗口内看不到新增组织关系，但必须继续读到原知识库和文档事实。

## 验证指标

- 存量文档迁移后，文档、当前发布版本、当前索引、可见范围和检索结果数量保持一致。
- 个人、企业、跨部门、停用成员和跨空间的文件夹、分类、知识域、检索和引用正反向测试全部通过。
- 文件移动、标签绑定、收藏和分类绑定不新增或修改 `DocumentVersion`、对象键与 Chunk。
- 发布审批通过前后只有授权的 `DocumentPublication` 指针变化；驳回和撤回不丢失版本。
- 任意跨空间关系、跨空间命中或跨空间引用阻断整次操作并写入安全告警。

## 迁移与回滚

1. 先兼容新增组织关系表和默认根目录，不修改现有知识表语义；所有新表使用复合工作空间外键和唯一约束。
2. 为每个工作空间创建唯一默认根目录，再按稳定排序分批将活动及已删除文档关联到根目录；批次可重跑且记录数量与摘要。
3. 新服务先双读：存在组织关系时返回新视图，缺失时按默认根目录兼容；迁移核对通过后再开启组织写入。
4. 回滚触发条件包括数量不一致、权限扩大、当前发布/索引指针变化或跨空间关系。触发后关闭新入口、恢复升级前快照并保留审计证据。
5. 一旦用户已写入文件夹、标签、分类或团队知识域，旧版本不能安全表达这些事实；此时不执行破坏性 Down Migration，只能回滚应用并从升级前恢复包恢复数据库。
