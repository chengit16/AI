# 交付、文档与 Git 管理规范

## 1. 目的

本规范用于保证每个阶段节点都具备明确范围、可复现验收证据和可追溯 Git 历史。它适用于阶段 0～6、条件容量认证以及项目后置能力。

## 2. 节点标识

每项可独立验收的工作必须具有稳定节点 ID：

- 阶段 0 使用 `P0-01`、`P0-02` 等编号。
- 阶段 1 使用里程碑加序号，例如 `P1A-01`、`P1C-03`。
- 阶段 2～5 使用 `P2-01`、`P3-01` 等编号。
- 阶段 6 使用产品子阶段加序号，例如 `P6A-01`、`P6B-04`。
- 容量认证使用 `CAP-01`，项目后置能力使用 `POST-能力名-序号`。

节点 ID 一旦进入 Git 历史不得复用。取消的节点保留记录并标记原因，不通过改号隐藏范围变化。

## 3. 节点完成定义

节点同时满足以下条件后才能标记为“已完成”：

1. 节点约定的代码、配置、契约或文档交付物已经产生。
2. 与风险相匹配的自动化测试、构建、容器冒烟或人工检查已经通过。
3. 验收命令、关键结果、已知限制和未执行项已写入阶段记录或验证报告。
4. `docs/project-progress.md` 已同步节点状态、完成日期和证据链接。
5. 相关架构决策、接口契约和操作文档已经同步，不存在明知失真的说明。
6. 当前节点的改动已形成一次独立 Git 提交，并在提交后回填提交 SHA。

代码已经实现但测试失败、验证环境缺失或文档尚未同步时，节点状态只能保持“进行中”或“受阻”。

## 4. Git 提交规则

每个完成节点必须对应一次独立提交，提交信息格式为：

```text
<type>(<节点 ID>): <中文摘要>
```

允许的主要类型包括：

| 类型 | 使用场景 |
| --- | --- |
| `docs` | 设计、计划、报告和规范 |
| `chore` | 工程骨架、依赖、构建和工具配置 |
| `feat` | 可使用的新能力 |
| `fix` | 缺陷修复 |
| `test` | 测试能力和数据集 |
| `refactor` | 不改变外部行为的结构调整 |

示例：

```text
docs(P0-01): 建立阶段交付与进度跟踪基线
chore(P0-02): 建立本地工程和一键运行骨架
feat(P1C-03): 实现菜单与接口统一授权
```

一个提交只完成一个节点；多个节点即使同时开发，也必须在各自验收后分别提交。纯粹修复当前节点验收问题的改动并入该节点提交；已提交节点的后续缺陷使用新的修复节点，不改写已经共享的历史。

## 5. 文档跟踪体系

项目持续维护以下文档：

| 文档 | 更新时机 | 内容 |
| --- | --- | --- |
| `ai-intelligent-platform-v2-design.md` | 架构或范围变化时 | 产品边界、平台架构、阶段规划和实施决策 |
| `docs/project-progress.md` | 每个节点开始、受阻或完成时 | 当前状态、完成比例、证据和提交 SHA |
| `docs/stages/stage-<n>-plan.md` | 阶段启动及范围变化时 | 建设顺序、节点依赖、交付物和门禁 |
| `docs/stages/stage-<n>-report.md` | 阶段验证过程中持续更新 | 环境、命令、数据集、实际结果、限制和结论 |
| `docs/decisions/ADR-*.md` | 关键方案确定或改变时 | 背景、选择、影响和回滚方案 |
| `contracts/` | 协议发生变化时 | OpenAPI、SSE、事件、错误码和策略接口契约 |

阶段报告采用持续更新方式，不等到阶段结束后补写。敏感凭证、真实个人信息和真实企业资料不得进入文档、测试数据或 Git 历史。

ADR 的触发、状态和取代规则执行 [架构决策管理规范](./architecture-decisions.md)。关键框架、模块接口、数据写入权、协议主版本、安全边界、部署方式和跨语言迁移发生变化时，必须先形成或更新 ADR，不能只在提交信息中说明。

## 6. 状态与验收证据

项目看板统一使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `待开始` | 依赖可能已满足，但尚未开始实施 |
| `进行中` | 已经开始，尚未通过全部完成门禁 |
| `受阻` | 存在无法在当前范围内消除的外部阻塞 |
| `已完成` | 交付、验证、文档和 Git 提交全部完成 |
| `已取消` | 经范围变更决策取消，并保留原因和决策链接 |

验收证据至少包含测试或检查命令、执行日期、结果摘要和对应文档路径。未执行的容量、真实供应商或 AI 质量验收必须如实标记为 `not_run` 或 `not_configured`，不得用 Mock 结果替代。

## 7. 阶段门禁

阶段只有在其全部必需节点均为“已完成”、阶段报告给出通过结论且不存在未处理的高风险问题时才能关闭。阶段关闭也形成独立提交和可识别 Git 标签；阶段 0 使用 `stage-0-complete`，其余阶段依此类推。

条件容量认证和项目后置能力不作为当前阶段关闭门禁，除非后续范围决策明确将其提升为必需节点。
